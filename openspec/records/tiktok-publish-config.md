### 自审抓到的三个真缺陷（本刀自己引入、已修）

1. **页面脚本常量跨平台同名 ⇒ 导入时静默拿到另一个平台的对象**
   TikTok 与 YouTube 都有「上传完成判据」，最初两边都叫 `UPLOAD_DONE_FN`
   ⇒ `require('./index').UPLOAD_DONE_FN` 拿到的是 **YouTube 的那个**
   ⇒ 用例锁错了对象还一度全绿。
   ⇒ 修法：TikTok 的三个常量一律加 `TIKTOK_` 前缀；并加**结构锁**「跨平台常量不得同名」。
2. **「编辑器里已有内容就跳过写入」是 fail-open 方向**
   原实现先读编辑器长度，> 0 就当「已写入」直接跳过 ⇒ 平台预填的**残留内容**会被当成我们的内容
   ⇒ 发的描述与我们写的不是一回事，却报成功。
   ⇒ 修法：**去掉该分支**，并把回读判据从「长度 > 0」升级为「**回读文本包含我们写入的文本**」。
   ⇒ 这条也把「残留内容」变成了一个**会红**的场景（新增用例锁住）。
3. **（第二遍自审）回读不匹配时继续换候选 ⇒ 会插入两次**
   候选循环里「插入成功但回读不匹配 → 换下一个候选再插一次」⇒ 编辑器里留下**两份文本**
   ⇒ 发的描述是**重复的**。
   ⇒ 修法：插入前先探候选是否存在（不存在就换，且不写入）；**一旦插入过就不得再换候选** ——
   宁可失败，也不产出重复内容。已加变异锁（M10）。

## learnings

### lesson: 「页面脚本常量」跨平台同名 ⇒ 导入时静默拿到另一个平台的对象

**现场**：TikTok 与 YouTube 都需要「上传完成」判据，两边最初都叫 `UPLOAD_DONE_FN`
⇒ `require('./index').UPLOAD_DONE_FN` 拿到的是**后导入的 YouTube 那个**
⇒ TikTok 的用例在断言一个**不属于 TikTok 的**函数。

**根因**：JS 的模块导出是**按名覆盖**的，后注册的同名导出会顶掉先注册的
⇒ 而「两个平台各有一个同名工具」是极自然的设计（每个平台都要判「上传好了没」）。

**判据（可复用的三条）**：
1. **跨平台/跨模块的导出常量必须带作用域前缀**（`TIKTOK_UPLOAD_DONE_FN` 而不是 `UPLOAD_DONE_FN`）。
2. ⭐ **加一条「同名不得共存」的结构锁**：从**真实 mixin 源码**读导出表，断言
   「不同平台的同名常量不存在」—— 否则等**真的**撞上时，用例可能已经在锁错的对象。
3. ⇒ **通则：同名导出的冲突不会报错，只会让某个平台拿到别人的实现** ——
   这与「两份手工同步的清单」同族（都靠机械锁兜住）。

### lesson: 「读到的非空」不等于「我写的」—— 残留内容会把 fail-open 伪装成成功

**现场**：描述编辑器回读长度为 0 时判失败是对的；但我最初加了个「幂等优化」：
**写入前先读一次，长度 > 0 就当已写入、跳过写入**。

**为什么危险**：TikTok Studio 的编辑器可能**预填了残留内容**（平台默认文案、草稿恢复）
⇒ 跳过后发的描述**与我们写的不是一回事**，却因为「回读非空」而报成功
⇒ **这是 fail-open 方向**（本仓的整套纪律都是往 fail-closed 走）。

**判据**：
1. ⭐ **「存在」不是「正确」** —— 写内容的回读判据必须是「**回读内容包含我们要写的内容**」，
   不是「回读长度 > 0」（前者能挡住残留，后者挡不住）。
2. ⭐ **幂等优化必须先问「它读到的是不是我自己写的那份」** ——
   在「读到的东西来源不明」时，**跳过写入比写错更危险**。
3. ⇒ **同族**：任何「已经填好了就不动」的短路，都要能区分「之前写的」与「别人填的」。

### lesson: 在 Electron 里**绝不能点** `<input type=file>` 的原生触发按钮

**现场**：TikTok 的参考实现是「点『Select video』按钮 → 等 file chooser → 塞文件」。

**为什么不能照搬**：那是 `<input type=file>` 的**原生触发点**
⇒ 在 Electron `BrowserWindow` 里会弹出**系统文件对话框**并**阻塞渲染进程**
⇒ 自动化脚本会卡死，且**阻塞的是用户看得见的窗口**。

**正解**：用 CDP `DOM.setFileInputFiles` 直接注入（仓内 `_setFileInput` 内部
`DOM.getDocument{pierce:true}` **能穿透 iframe** 找到 iframe 内的 input）。
**找不到 input ⇒ 明确失败**，不点按钮。

**判据**：移植 RPA 实现时，凡是「点击会打开原生对话框」的动作（文件选择、另存为、打印）
⇒ **必须换成等价的程序化路径**，否则自动化会在真机上卡住。
⇒ 已加变异锁（M9：点了那个按钮 ⇒ 用例红）。
