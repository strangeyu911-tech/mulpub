# PRD：设计令牌双轨收敛 —— 第一步「别名映射」（阶段 3.5，design-token-single-track）

- 关联审计：`01-docs/UX-AUDIT-2026-10-17.md` 阶段 3 的 3.5（audit-26 令牌双轨）
- 执行记录：`openspec/records/design-token-single-track.md`
- 范围：仅 `apps/desktop/src/styles/` 的**令牌定义层**与两道锁；**不改任何消费者**、不动组件模板
- 性质：CSS 令牌声明改写（按值逐字相同 ⇒ 零视觉回归）+ 测试；不含主进程、不含 IPC、不含 `.github/workflows/`

## 1. 现状与取证（当场量的，不是设想）

同一份设计语言在两个文件里各写了一套令牌，**名字不同、部分值相同**：

| 族 | 定义处 | 消费者数（`var()` 引用，非测试域，当场实测） |
|---|---|---|
| `--radius-{xs,sm,md,lg,xl,pill,full}` | `tokens.css` | 36 / 61 / 29 / 14 / 0 / 5 / 27 ＝ **172** |
| `--r-{xs,sm,md,lg,xl,pill,full}` | `cohere-design-system.css` | 23 / 33 / 4 / 7 / 1 / 12 / 13 ＝ **93**（评审 i5：本行原先写 83，与逐格求和不等＝抄错） |
| `--space-{xxs,xs,sm,md,lg,xl,xxl,section}` | `cohere-design-system.css` | sm 144 / md 129 / lg 70 / xl 31 / xxl 10 / xs 12 ＝ **396+** |
| 本批参与的 `--spacing-{2,3,4,6,8}` | `tokens.css` | 127 / 69 / 20 / 12 / 2 ＝ **230**（评审 i5：原表写 2→124、6→18，与棘轮现场读数 127 / 12 不符；124 那次是在**滞后 234 个提交的共享根**上量的） |
| `--spacing-1` 等未参与档 | `tokens.css` | 1→45；其余档位本批不动，刻度冲突档见 §3 |

值层面：`--radius-*` 与 `--r-*` **逐字相同**（4/8/12/16/20/32/9999px）；`--space-*` 与 `--spacing-*` 只在 5 个档位上等值（8/12/16/24/32px），其余是**真实刻度冲突**（2 与 4、6 无对应、20、40、64 与 80）。

为什么这是缺陷而不只是"不优雅"：两侧各自写死数字，任何一次"这个组件圆角差 2px"的局部回写都会让同名令牌在不同文件里给出不同结果，表现为**同名不同视觉**的偶发 bug，且 CSS 层不会报错。本仓对同类问题已有先例（正文承载形态 `formatArticleBody`、href 协议 `safe-http-url`、CJS/ESM 孪生靠 parity 锁），**唯独设计令牌这一维没有单一实现约束**。

## 2. 本批目标与非目标

**目标（第一步）**
1. 把"值本来就相同"的档位收敛到**单一真源**：被废弃侧改成 `var(存活令牌)`，不再持有字面值。
2. 让"重新写死字面值"这件事**当场变红**（漂移锁），而不是等下一次视觉回归才发现。
3. 把"值不同所以不能合并"的档位显式登记成**冲突清单**（带理由、只能缩小），而不是用"统一取一边"把差异抹平。

**非目标（刻意不做）**
- 不改任何消费者（第二阶段按文件批次把 `var(--r-*)` 换成 `var(--radius-*)`，每次换都要跑像素门禁）。
- 不合并刻度冲突档（20/40/64 与 2/6/80）：谁胜属设计决策，会改可见留白，须与视觉基线刷新同批（基线只能取同一次 CI 渲染）。
- 不动 `cohere-design-system.css` 的其它令牌（颜色族双轨是另一件事，本批只处理审计点名的 space/spacing、r/radius）。

## 3. 存活方选择规则（不靠偏好）

存活方 = **消费者更多的一侧**（存量迁移成本更低的一侧留作真源），当场实测：radius 族留 `--radius-*`（tokens.css），spacing 族留 `--space-*`（cohere）。⚠️ 口径固定：**存活方由棘轮当场打印的废弃侧读数决定，本文不再手抄合计**——原先那句里的 83 / 172 / 278+ 三个数正是手抄出来的矛盾源（i5）。读数现场 = `[TOKEN-RATCHET]` 那一行与执行记录。。因此两族的别名方向**相反** —— 这不是不一致，而是同一规则的两处应用；规则本身写进测试注释与本文。

## 4. 数据校验口径（令牌层）

| 项 | 口径 | 失败时的表现 |
|---|---|---|
| 别名右侧 | 必须恰好一条声明，且形如 `var(--存活令牌)` | 出现 `px` 字面值 ⇒ 漂移锁红并点名那条令牌 |
| 存活侧 | 必须恰好一条声明且是字面值（不得也指向别处），且该声明位于 `:root` 块内 | 两侧互相引用 ⇒ 悬空/环 ⇒ 红；落在别的选择器 ⇒ 部分元素不可继承 ⇒ 红 |
| 装配（跨文件依赖） | `main.js` 必须以**未注释的整行 import** 同时装载两份令牌文件 | 少一份或把 import 注释掉 ⇒ 别名在该上下文 guaranteed-invalid ⇒ 红（评审 i2；第一版用全文正则，被"注释里的同名串"顶掉，已由变异 T7 打回并改为按行匹配） |
| 生效值 | 快照锁按**解析 var 之后**的值断言（不是文本） | 别名指向被改 ⇒ 快照不等 ⇒ 红 |
| 零回归证据 | 两件事：① 测试内冻结表要求两侧值逐字相同（自洽）；② **该表必须与 `git show origin/main` 的改动前 blob 逐项相等**（评审 i3：只自洽的表可以"对称抄错"全链路漏过）。合并后 blob 不再含字面值时，用例打印退化说明而不是静默通过 | 抄错 ⇒ 与 git 比对红；本批偷偷改了刻度 ⇒ ①②双双红 |
| 冲突清单 | 每条带 >20 字理由；登记项指向的令牌与字面值必须当场仍能在源里读到；**规模下界 = 实测档位数** | 陈旧登记 ⇒ 红；掏空清单 ⇒ 下界红（掏空会让逐条校验对空集恒真） |
| 存量棘轮 | **两侧全部 12 个废弃名**（`--r-*` 7 档 + `--spacing-*` 5 档）消费者数 ≤ 当场实测上界，每次跑打印读数；`rows.length === ALIASES.length` 作域完整性断言 | 新代码用废弃名 ⇒ 红；只量一族 ⇒ 条数断言红（评审 i1）；遍历域塌空 ⇒ 同一条红 |

## 5. 显示项与用户可见结果

本批**不改变任何用户可见像素**（值逐字相同 ⇒ 渲染结果一致），因此不刷视觉基线；判据是 `QG Visual` 必须继续绿，而不是"我推断不会变"。文案、交互、提示词均无变化；新增的唯一"提示"是锁的失败信息，形如「以下令牌已不再是纯别名：--r-sm = 10px（应为 var(--radius-sm)）」，指回单点真源这一诉求。

## 9. 硬约束：这两份文件都在行数熔断的点名清单里（第二阶段必读）

`tokens.css` 与 `cohere-design-system.css` 不是普通样式文件，它们是 `.github/scripts/check-max-lines.js` 的**点名还账对象**，因此本批改动的接受面是**行数**，不只是内容：

| 文件 | 判据 | 实测读数（本批第一版） | 后果 |
|---|---|---|---|
| `tokens.css` | `NEW_OVER_LIMIT`：行数 `>= 500` 且 base 时不超限 ⇒ 红 | base 499 行 / 第一版 502 行 | 只剩 **1 行**余量；任何净增一行的改动都会把它顶过 500 |
| `cohere-design-system.css` | `TARGET_GREW`：现行数超过 `targets` 里的点名目标 ⇒ 红（**零增长容差**） | 点名目标 1698 行 / 第一版 1699 行 | 目标以下才算合规；上调目标必须与真实清理同 PR |

三条不可破：

1. **注释也是行**。为解释设计取舍而新起的多行注释块，在普通文件里成本为 0，在这两份文件里是硬熔断。正解是把说明**写进它描述的那一行**（本批最终形态：`tokens.css` 的间距阶梯行、`cohere-design-system.css` 的圆角行各带一条单行注释），而不是在文件顶部另起一段 —— 后者除了顶熔断，还把"说明"与"被说明的声明"隔开 40 行，下次改动最容易整块丢失。
2. **不得靠调 `limit` / 调 `targets` / 挂墓碑交账**。这三条路径的语义分别是"放宽全局熔断"、"把还账目标改成欠账额度"、"永久豁免"，都与本批的实际清理量无关。合规做法只有一个：压自己的新增。
3. **第二阶段（消费方换名）天然满足这条**：把 `var(--r-md)` 换成 `var(--radius-md)` 是逐字符替换、行数不变，而清理两侧都声明过的重复档位是净减行。真需要净增行时（例如新增一个此前不存在的语义档位），必须**同 PR 抽出一段**（把某个选择器块拆成独立文件并 `@import`），使两份文件各自退行 —— 与 `AGENTS.md` 里 App.vue 那条"下一次触碰它必须先抽一段出来"同一口径。

取证命令（本批实跑；后两条在 CI 的同一个 step 里顺序执行，缺一条就等于没跑）：

```
node scripts/check-debt-budget.js            # 全仓聚合棘轮：五项指标 vs 基线
node .github/scripts/check-max-lines.js      # 逐文件：新代码不得引入超大文件、点名还账零增长
node --test .github/scripts/check-max-lines.test.js
```

两条判据**互不替代**，且本批的红只被第二条看见：`check-debt-budget.js` 的 `filesOver500` 量的是**数量**，一份文件从 499 涨到 502 不改变数量，所以它当时全绿。反过来，把 `tokens.css` 拆成两份也**不会**让聚合棘轮变松 —— 它把一个超限文件变成零个，那是真还账，不是调口径。
