## 0. 一句话

把「多平台发布」从**一堆同色圆角卡片**变成**一张可读的信号地图**：
**颜色 = 目的地（哪个平台），形状 + 图标 + 文案 = 状态（到哪儿了）**。

现状里 14 个平台的徽标全是同一种灰蓝胶囊，用户必须靠读文字区分；本稿把平台色变成一等公民，
同时把状态从颜色里剥离出来，解决「红到底是小红书还是失败」这类歧义。

## 1. 定稿决策一览

| 决策项 | 结果 |
|--------|------|
| 应用外壳 | **靛蓝单色玻璃**：浅底 + 靛紫渐变光斑 + 霜化层 + 白卡浮起（只此一档） |
| 工作区 | 冷灰阶浅色纸面 + 白色卡片 + 1px 发丝线，**零色相** |
| 彩色层归属 | **颜色 = 目的地**（14 个平台各一色）+ Hero 渐变；状态一律用字形 |
| 状态表达 | ● 投递中 / ✓ 已完成 / ! 失败 / ○ 待发 / △ 需授权 |
| 签名元素 A | **信号轨** —— 一排带平台色的投递节点，回答「这份内容现在到哪儿了」 |
| 签名元素 B | **Hero 系统** —— 每屏一条渐变横幅，回答「这一屏现在是什么状态」 |
| Hero 覆盖 | 13 个应用屏 + 弹窗 / 下拉浮层 / Toast |
| Hero 色族 | 靛紫=状态总览 · 青蓝=生产执行 · 品红=洞察计划 · 琥珀=商业额度 |

| 侧栏底部 | 浅色/深色切换（深色为占位，主题待设计）· 服务状态 · 用户条 · 隐私政策/服务条款 |

## 2. 设计主张

| # | 主张 | 落地方式 |
|---|------|---------|
| 1 | 颜色只表示目的地 | 14 个平台各一个身份色，界面其余部分零色相 |
| 2 | 状态只由形状承担 | ● / ✓ / ! / ○ / △ 五种字形 + 文案，颜色一律不用 |
| 3 | 主按钮用墨色不用彩色 | 唯一实心主按钮 `#15181F`；彩色实心只出现在「按平台投递」处 |
| 4 | 焦点环用墨色不用蓝 | 避免与知乎蓝等平台色抢读；全应用一套，不按深浅切换 |
| 5 | 相近色平台必须与官方图标同现 | 小红书与微博同属红系，纯色块无法区分 → 图标 + 名称 + 颜色三重编码 |
| 6 | 所有数字等宽 | Cascadia Mono + `tabular-nums`，刷新时数字不跳动 |
| 7 | 浏览器式 chrome 不动 | 标签栏 38px + 地址栏 38px = 76px，沿用主进程 `WebContentsView` 契约 |

## 4. Hero 系统

Hero 从「首页的一张图」升级为**全应用的一套系统**：每个页面顶部一条渐变横幅，
弹窗、下拉浮层、Toast 同样吃这套渐变。

### 4.1 色族（按语义分）

| 色族 | 语义 | 覆盖页面 |
|------|------|---------|
| **靛紫** | 状态与总览 | 首页、数据洞察、投递队列 |
| **青蓝** | 生产与执行 | 一键发布、账号、视频创作、素材采集 |
| **品红** | 洞察与计划 | 发布日历、选题雷达、私信与评论 |
| **琥珀** | 商业与额度 | 会员中心 |

同色相的页面归为一族，换页就能感知业务域变了。

### 4.2 尺寸（按位置分）

| 档 | 形态 | 用在哪 |
|----|------|-------|
| 整页横幅 | 标签在上 / 数值在下 / 注脚第三行，四列用竖线分隔 | 首页、数据洞察 |
| 单行横幅 | 图标 · 标签 · 数值 · 注脚 同一行 | 其余全部页面 |
| 卡片内小条 | 压到 26px 图标、17px 数值 | 侧栏卡片、抽屉 |

> **紧凑档必须单行。** 三行式紧凑 Hero 会让每屏多占约 40px，47 屏全部溢出；
> 改成单行后每屏只占约 58px，页面信息密度不受影响。

### 4.3 浮层形态

| 形态 | 做法 |
|------|------|
| 主弹窗 | 弹窗头用当前色族的渐变 + 星点噪点，白字标题与副标题 |
| 下拉浮层 | 同样的渐变头，更矮，只有标题 |
| Toast | 左侧 4px 渐变竖条，主体仍是白卡 |

### 4.4 落地规则

1. **Hero 承载 KPI，页面不再重复摆统计卡。** 加 Hero 后，原来那排「本月总发布 / 成功 / 失败待处理 /
   在管账号」的统计卡被删除（数据洞察页同理），避免同一组数字在两处出现。
2. **浮层用当前页面的色族**，不另起一套。
3. **首跑引导页没有卡片式 Hero**，改用**渐变文字**（`background-clip:text`）做大标题——
   引导页的视觉主体是那句话本身，不是数据。

### 4.5 渐变网格做法（整页横幅）

```css
background:
  radial-gradient(56% 92% at 8% 10%, rgba(122,107,216,.95) 0%, transparent 62%),
  radial-gradient(44% 78% at 36% 0%,  rgba(167,139,250,.90) 0%, transparent 60%),
  radial-gradient(50% 84% at 66% 24%, rgba(240,166,200,.86) 0%, transparent 62%),
  radial-gradient(56% 88% at 95% 54%, rgba(155,211,232,.86) 0%, transparent 60%),
  radial-gradient(70% 94% at 54% 110%,rgba(247,227,200,.82) 0%, transparent 58%),
  linear-gradient(118deg, #6455C9 0%, #8A78DE 34%, #E7A6CF 66%, #C9E7F2 100%);
```

星点用内联 SVG（四芒星 + 小圆点）平铺，`opacity:.55` 叠在最上层。
圆角 20px，投影带紫调：`0 2px 6px rgba(90,70,190,.16), 0 18px 44px rgba(90,70,190,.16)`。

其余三族（青蓝 / 品红 / 琥珀）同结构换色，见 `index.html` 的 `.hero-fam-*` 变量。

## 5. 组件规格

### 5.1 状态字形

| 状态 | 字形 | 容器 | 文案示例 |
|------|------|------|---------|
| 已完成 | ✓ | 15px 墨色实心圆，白字 | 已完成 |
| 投递中 | ● | 1.5px 墨色描边圆 + 呼吸点 | 投递中 |
| 失败 | ! | 15px `#F7E9EA` 底 + `#A8232B` 字 | 授权失效 |
| 待发 | ○ | 15px `#EDF0F4` 底 + `#949CA9` 字 | 待发 |
| 需授权 | △ | 15px `#FBF1E0` 底 + `#B4750E` 字 | 需授权 |

### 5.2 外壳：靛蓝玻璃的四层结构

```
① 渐变底      .side background: var(--glass-base)              不透明线性渐变
② 模糊光斑    .side::before  filter: blur(26px) saturate(150%) inset:-14% 溢出裁切
③ 霜化玻璃    .side::after   backdrop-filter: blur(12px) saturate(135%)
                        + 顶部受光 radial-gradient(85% 55% at 0% 0%, rgba(255,255,255,.34))
                        + 细腻颗粒 140x140 feTurbulence（opacity .035）
④ 内容层      .side > * { z-index: 2 }                          文字/导航/用户条压在玻璃之上
```

- 导航项：未选中 = 透明，文字 `#454C59`；选中 = 半透明玻璃胶囊
  （`rgba(255,255,255,.82)` + 1px 描边 + 极轻投影 + 左侧 3px 靛蓝渐变竖条）。
- 标签栏：激活页签白底、圆角 7px 7px 0 0，与白色地址栏相连（浏览器标签手感）。
- 地址胶囊：白底 + 1px `#DFE4EA` + 极轻投影。

> 高饱和的 `saturate(165%)` 是「廉价玻璃感」的来源，本稿降到 `135%`。

### 5.3 卡片语言

| 元素 | 规格 |
|------|------|
| 卡片 | 圆角 18px，`0 1px 2px rgba(14,16,21,.04)` + `0 10px 28px rgba(14,16,21,.05)` |
| 统计卡 | 圆角 16px，投影更轻 |
| 卡片内嵌卡 | 圆角 14px + 1px 发丝线，用于卡片里的卡片 |
| 按钮 / 分段控件 / 标签 | 全圆角 999px |
| 输入框 | 圆角 12px |

### 5.4 目标矩阵（发布页右侧）

```
[平台徽标] 平台名   [账号胶囊 × n]      [勾选框]
```

- 账号胶囊：19px 圆形徽标 + 账号名，选中态描边用平台色。
- 勾选框：选中填充平台色；异常态（授权失效）用 `#A8232B` 描边 + `!`。
- 底部固定：发布时间、评论转发、失败重试三个开关 + 主按钮「投递到 N 个目标」，N 随勾选实时变化。

## 6. 落地约束（与现有代码的对齐点）

| 约束 | 现状 | 本稿 | 实现时需注意 |
|------|------|------|-----------|
| 标签栏 + 地址栏高度 | 40 + 40 | 38 + 38 = 76 | 主进程 `WebContentsView` 的 `TOP=76px` 契约**保持不变**，不动 |
| 侧边栏宽度 | 200px | 220px | 需同步更新 `setSidebarWidth` 同步链与折叠态宽度（≤900px 折叠为 68px） |
| 浏览器式标签栏 / 地址栏 | 保留 | 保留 | 登录标签仍走 WebContentsView，样式不变 |
| 深色模式 | `prefers-color-scheme` + `html.dark` | 本稿只出浅色 | 按同一套令牌反相：骨架色阶翻转，**平台色与 Hero 渐变不变** |
| 平台图标来源 | `src/assets/platforms/*.svg` | 直接复用 | 无需新增素材 |
| 品牌 Logo | `src/assets/brand/tom-fish-logo.png` | 直接复用 | 无需新增素材 |
| 信息架构 | 主页/发布/账号/数据/视频创作/采集 + 更多 | 重排为 工作台 / 生产 / 分发 / 洞察 四组 | **这是产品决策**，需确认后再改 `MpSidebar.vue` |
| `backdrop-filter` | 渲染层可用 | 侧栏霜化层依赖它 | Electron 的 Chromium 支持；需确认 WebContentsView 覆盖区不受影响 |

## 9. 复现与自检

### 9.1 `index.html` 是构建产物，不是手工维护的源文件

- 它是**自包含单文件**：品牌 Logo 内联为 data URI、平台图标为同目录 SVG、CSS 与 Hero 渐变内联在
  `<style>` 里。目的是**离线自包含** —— 双击可开、整目录拷贝不丢、不会因相对路径失效而白屏。
  这是交付形态约束，不是"忘了拆"。
- **可编辑的源与渲染脚本不在本仓**：源文件、渲染/量测/对照脚本都在设计工作副本里，产出后由脚本
  生成本目录的 `index.html` 与 `screenshots/*.png`。**本仓只存产物与规格**，因此本仓没有渲染脚本。
- 因此 §9.2 的命令请在**设计工作副本的根目录**执行，不要在本仓执行。
- 要改样式时的正确顺序：改源 → 重新渲染 → 覆盖本目录产物 → 产物与 `screenshots/` **同一次提交**，
  避免「HTML 与截图不同步」——这与本仓 `01-docs/ui-reference/visual-baseline-manifest.json`
  那条视觉基线纪律是同款要求。

### 9.2 渲染与自检（在设计工作副本执行；本仓不含这些脚本）

## 10. 状态变体：每个页面都要有主态之外的第二屏

### 10.1 为什么补状态屏

第一版只出了 13 个应用屏的**主态**。实现时发现：主态是「一切正常」的样子，而用户实际最常遇到的是
**空 / 加载 / 失败**——这三种状态下页面长什么样、用户能做什么、界面上如何说清「发生了什么」，
原稿完全没给。结果是每个页面在实现时都要临场决定，而临场决定必然不一致。

本版把 22 个遗漏页面补齐时，**按源码里真实存在的状态分支**各出一屏（不是每页都硬凑四种）：

| 状态 | 字形 | 语义 | 页面必须说的话 |
|------|------|------|---------------|
| 空态 | ○ | 没有数据 | **区分「本来就没有」与「筛完没有」** —— 后者要给回退动作（清空筛选） |
| 加载态 | ◐ | 正在取 | 用**骨架**而不是转圈遮罩（骨架说明「等完会看到什么形状」） |
| 失败态 | ! | 出错了 | **区分「读不到」与「没有」** —— 前者不能显示「暂无数据」，那会把故障说成事实 |

### 10.2 三条硬规则

1. **失败态不许显示「暂无数据」**。读不到真源和真源为空是两件事，混为一谈会把故障伪装成事实
   （`/automation`、`/library` 两页的源码里都有这条区分：状态不可读时连列表都不渲染）。
   对应屏：`20 自动化任务 · 失败态`、`26 项目库 · 失败态`。
2. **空态要给可执行动作**，不能只说「暂无」。文案要指向**下一步**而非复述现状。
3. **加载态用骨架屏**，骨架的形状 = 数据到达后的形状 ⇒ 加载结束时版面不跳。

### 10.3 Hero 在状态屏上的口径

状态屏的 Hero **不给假数字**。读不到时用「—」并配「状态未知」说明，不填 0 也不填上次缓存值
（对应屏：`20 自动化任务 · 失败态` 的 Hero 四个 KPI 全是「—」）。

### 10.4 覆盖情况

| 类别 | 屏数 | 说明 |
|------|------|------|
| 主态 | 22 | 每页一屏 |
| 空态 | 9 | 仅源码里存在空态分支的页面 |
| 加载态 | 3 | 仅源码里存在加载/骨架分支的页面 |
| 失败态 | 4 | 仅源码里存在错误分支的页面 |

合计新增 33 屏，与原 13 应用屏 + 1 总览 + 1 浮层 = 15 屏相加，本版共 **47 屏**。

## 12. 设计稿导航（顶部锚点栏）

设计稿顶部有一排锚点链接，47 屏各占一个。规则如下：

| 规则 | 说明 |
|------|------|
| 编号 | 同一页面的多个状态屏**共用编号**（如 20 的三个状态屏都是「20」）⇒ 编号表达「第几页」 |
| 标题 | 状态屏标题**必须带状态后缀**：`主态`（可省略）/ `· 空态` / `· 加载态` / `· 失败态` / `· 工作台` / `· 经典模式` |
| 唯一性 | **47 个链接的文字两两不同** —— 这是硬约束，不是风格偏好：重复文字会让读者点进去分不清是哪一屏 |
| 对应关系 | 链接文字 = 屏的 caption 标题（`00 设计总览` … `40 回放时间轴`），锚点 = 屏 id（`s-automation-empty` 等） |

**为什么强调唯一性**：本稿的 33 屏里有 13 屏是状态屏，若沿用「主态标题」不加后缀，
「20 自动化任务」会在导航里出现 3 次（主态 / 空态 / 失败态）⇒ 导航失去区分能力。
**标题后缀是状态屏的可见标识**，与屏内 Hero 的状态字形（● ✓ ! ○ △）是两套互补的语言：
字形说「状态是什么」，后缀说「这是哪一屏」。

### 12.1 六条硬契约（已由 CI 门禁机检）

上表是给人读的规则，下面六条是**机器逐条判定**的契约。改了 `index.html` 的导航或
任何屏的 caption，这六条任一破了 CI 就红。

| 代号 | 契约 | 判定口径 |
|------|------|----------|
| D1 | **无死链** | 每条导航链接的锚点必须等于某个真实屏的 `id` |
| D2 | **文字唯一** | 47 条链接文字两两不同，重复即红 |
| D3 | **一一覆盖** | 每个屏恰好在导航里出现一次（漏挂 / 重复挂都红） |
| D4 | **文字 = caption** | 导航文字必须**逐字等于**目标屏 caption 的「编号 + 屏名」 |
| D5 | **同页同号** | 同一编号组内，各屏屏名的基名（`·` 之前那一段）必须相同 |
| D6 | **组内互异** | 同一编号组内，各屏屏名必须互不相同 |

**两条口径，写下来免得后人重犯**（都是实测踩过的坑）：

1. **比唯一性时不许剥状态后缀再比。** 剥掉后「20 自动化任务」与「20 自动化任务 · 空态」
   会被判成重复 —— 这是把「主态」和「状态屏」混成一回事，正好抹掉本稿最核心的设计。
2. **核查对象必须是仓内产物**（`01-docs/ui-reference/design-2026-10/index.html`），**不是**设计源工作副本。
   两份不同步时，核设计源得出的「没问题」对仓内稿不成立。

### 12.2 门禁住在哪、为什么

- 判据本体：`scripts/check-design-nav.js`（退出码 0 过 / 1 违约 / 2 判据自身故障）
- 回归锁：`scripts/check-design-nav.test.js`（14 例，含「把产物改坏必须转红」的可证伪用例）
- CI 接线：`quality-gate.yml` 的 **`changes` job**，在 docs-only 判定与「非 PR 早退」之前

**为什么是 `changes` job 而不是 `static-gates`**：本判据的输入 `01-docs/**` 命中 docs-only 白名单，
而 `static-gates` 整个 job 带 `if: needs.changes.outputs.docs-only != 'true'` ⇒ 只改设计稿的 PR
会把它整片跳过。那样一来「把导航改回文字重复」的 PR 能全绿合入，靠 main push 才红 ——
本仓已发生过同形事故（#3114）。这条理由与白名单里其它几条一致，见
`AGENTS.md` 的「进白名单前提锁」。

**判据自身故障必须与「没有问题」分开**：产物缺失、导航容器或屏结构变了、解析出 0 条链接，
一律退出码 2，不许静默发绿。「门禁瞎了」读成「没问题」是本仓最忌的装饰性门禁。
