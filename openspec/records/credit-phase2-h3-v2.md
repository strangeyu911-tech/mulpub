## 4. QM-5 Bug 反思循环（5 步）—— 仅针对 ⑤（`getVideoStatus` 入参形态）

### 4.1 找到第一性原因

| 缺陷 | 第一性引入点 | 引入时的动机 | 动机对不对 |
|---|---|---|---|
| 经 `callAdapter` 的 MiniMax 视频轮询必然失败 | `adapters/minimax.js` 的 `getVideoStatus(taskId)`（字符串签名） | 按「上游 API 只需要一个 task_id」建模 | ✅ **动机对，接口假设错** —— 仓内统一契约是「适配器方法收**一个对象**」，字符串形态只在直接调用时成立 |

⇒ **一句话根因**：**适配器方法签名没有对齐仓内「统一参数对象」这条调用契约**，
而这条契约在别的适配器（`agnes-video.js`）已经落地了 ⇒ 本文件是**漏改**而不是**新错**。

### 4.2 追溯测试逃逸（为什么没被测出来）

| 既有覆盖 | 实际断言了什么 | 为什么漏掉本缺陷 |
|---|---|---|
| `minimax.test.js` 的 6 条 v1 轮询用例 | 直接调 `adapter.getVideoStatus('t1')`（**字符串**） | **只覆盖了字符串形态** ⇒ 对象形态那一格从未被构造 |
| `agnes-video.js` 的同类用例 | 覆盖了对象形态 | 在**别的文件**里 ⇒ 本文件漏改没被任何跨文件断言发现 |

⇒ 逃逸链：测试只喂字符串 ⇒ 对象形态不可达 ⇒ 生产调用链（`callAdapter`）**只喂对象**
⇒ 两者永不相交 ⇒ 缺陷在 CI 全绿下活了下来。

### 4.3 识别系统性漏洞

**类别**：**「同一仓内契约，多个实现点各自落地」** ⇒ 没有一处断言把「调用方怎么调」与
「被调方怎么收」钉在一起 ⇒ 漏改不会被发现。
⇒ 对照组：`agnes-video.js` 里那段注释（「callAdapter 统一以 params 对象调用……两种都兼容」）
是**人写给人看的**，没有机械判据 ⇒ 下一个适配器照样可能漏。

### 4.4 修复 + 回归保护测试

- **修复**：入参归一化（对象 ⇒ `videoId || taskId || id`；否则原样），
  **写法与 `agnes-video.js` 逐字同型**（不发明第二种写法）。
- **回归保护**：`minimax.test.js` 新增用例「callAdapter 的对象形态 { videoId, taskId } 可用」，
  断言 URL 里出现 `task_id=mm-task-1` 且**不含** `object`。

### 4.5 防止再次发生

1. 归一化只有一处实现，且与仓内既有写法同型 ⇒ 下一个适配器照抄即可。
2. **变异验证 M10** 把这条钉住 ⇒ 有人改回字符串-only，对应用例当场红。
3. ⛔ **但本片只修了 MiniMax 一家**：其余视频适配器（`kling`/`veo`/`wan`/`seedance`/`runway`/`cogvideo`）
   的 `getVideoStatus` **仍是字符串签名** ⇒ 若它们经 `callAdapter` 被调用，同样会拼成
   `[object Object]`。**这是既有面更大的同类缺陷，本片不扩大打击面** ⇒ 登记为遗留 L-10（需独立评估）。

## 5. 关键设计取舍（含被否掉的方案）

| 取舍 | 决定 | 理由 |
|---|---|---|
| v1/v2 怎么选 | **按 model 族**（`MiniMax-H3` 前缀） | 轮询时拿不到 model ⇒ 选路必须发生在**创建时**并被记下来；按前缀判定还能自动覆盖官方未来的 H3 变体（**不复制官方枚举**） |
| v2 基址怎么来 | **baseUrl 同域换版本**推导 + `baseUrlV2` 显式覆盖 | 官方国内/国际站域名在第三方资料里有四种说法 ⇒ **赌错就是 401/DNS 失败**；用户已经填了 baseUrl（他知道买了哪一站）⇒ 推导优于内置 |
| 画幅从哪来 | `readAspectRatio`（单一真源）→ `width/height` 推导 → 有帧 `adaptive` → 报错 | 仓内画幅契约已有单一真源（`_base/aspect-ratio.js`）；影视工程只给 `width/height` ⇒ 推导是唯一现成通道；官方要求 t2va 的 ratio 必填 ⇒ 缺就报，不替用户猜 |
| 有帧时画幅怎么办 | **恒发 `adaptive`** | 官方对图生视频的非 adaptive 值是「**接受但忽略**」（没有任何提示）⇒ 发 `adaptive` 是唯一不会「看起来传了、实际没生效」的选择 |
| 官方取值域要不要落地 | **不落地**，只拦已知错配 | 官方改档位后，本地那份枚举会变成第二份真源 ⇒ 必然漂移。只拦「v1 老档位发给 v2」这种**确定性**错误 |
| 裸 base64 参考图 | **拒绝**，不猜 MIME | 猜错 = 发出一个「能提交但图裂了」的请求 ⇒ 静默失败比报错更坏 |
| v2 失败/取消要不要抛错 | **不抛**，返回 `status` + `error` 字段 | 仓内三个轮询方读的是 `status`（`['failed','error','cancelled']` ⇒ 收口）；抛错会被它们当成「还没出结果」⇒ **继续轮询到超时** ⇒ 反而掩盖了失败原因 |
| 缺 `usage` 怎么办 | `null`，**不补默认值** | 官方计费口径是 `usage.total_seconds`；补一个猜出来的值就是错账（且看不出来） |
| 轮询选路记在哪 | **适配器实例内的 Map**（`taskId → true`） | 适配器实例按 providerId 缓存（`_adapterCache`）⇒ 同一会话内创建→轮询必命中；进程重启后 Map 为空 ⇒ 走「v1 不认识才回落 v2」 |
| 回落什么时候发生 | **只在 v1 端点回答「不认识这个 task」时**（判别靠**状态码位数**，不靠文案） | 鉴权/限流/余额/5xx 换端点也是同样结果 ⇒ 多打一次请求只是放大上游压力；业务码 4 位 vs HTTP 3 位是稳定判别 |
| v1 代码怎么动 | **逐字保留**（只从 `getVideoStatus` 挪到 `_getVideoStatusV1`） | v1 是**在产**路径（Hailuo 仍在用）⇒ 行为零回归优先于结构好看；既有 6 条 v1 轮询用例 + 4 条 v1 创建用例全绿即是证据 |
| 逻辑放哪 | **独立模块**（`minimax-h3-v2.js`） | v1/v2 两套形状的分支多（画幅/时长/帧/状态/错误）⇒ 混在一个文件里没法逐条钉死；且 `minimax.js` 399 行仍在 500 上限内 ⇒ **不需要动任何基线** |
| H3 怎么进 UI | 预设模型列表追加两个 id（**一行**） | 预设是「新装用户唯一的模型来源」；不追加的话用户得手动敲模型名。追加项**不影响默认模型**（`models[0]` 不变）⇒ 零行为回归 |
| 官方 Key 池路由 | **不在本片** | 依赖 ops-center `POST /api/v1/compute/execute`，而它依赖 R5-4 的价格卡（U-12 未拍板）⇒ 无价卡必然「缺价 ⇒ 拒绝服务」⇒ 价值低、等 U-12 |

- MiniMax H3 走的是**另一套端点**（提示词在数组里、查询用路径参数、产物直接给链接），
  原来的适配器完全不认识它 ⇒ 现在按模型自动选路，Hailuo 等老模型行为**一行未改**。
- 官方会回一块真实用量（**实际出了多少秒**）；这块数据被原样透出 ⇒
  成本不再靠「请求了多少秒」去猜（官方按帧网格取整，两者本来就不相等）。
- 顺手修掉一个既有缺陷：轮询接口只认字符串参数，而仓内统一传的是对象 ⇒
  MiniMax 的视频轮询经正常调用链**必然失败**。修法照抄仓内既有的同类适配器写法。
- 画幅、时长、分辨率**缺什么就报什么**：不猜裸 base64 的图片类型，不替官方复制取值域，
  也不把「看起来传了画幅、实际被忽略」当成功。
- 官方域名**不写死在代码里**：国内站与国际站的域名在资料里互相矛盾，
  改成「按你配的地址同域换版本」⇒ 配哪个站就打到哪个站。

## learnings

### lesson: dont-hardcode-a-domain-when-sources-disagree

**现场**：要给 MiniMax H3 接 v2 端点，就得知道基址。可官方国内站/国际站的域名在第三方资料里
有四种说法（`api.minimaxi.com` / `api.minimaxi.cn` / `api.minimax.cn` / `api.minimax.io`），
连「国内端点示例」都互相引用着不同的域名。

**根因**：**这不是一个「查清楚就能写死」的常量，而是一个「用户本来就知道」的量。**
用户已经在服务商设置里填了 baseUrl（他知道自己买的是哪一站的额度）⇒
代码再去猜一个官方域名，等于**用一个更不可靠的知识覆盖一个更可靠的知识**。

**可复用的 3 条**：

1. **当多个来源对同一个「外部标识」不一致时，不要选一个信** ⇒ 改成**推导**：
   本例是「同域换版本」（`.../v1` ⇒ `.../v2`）⇒ 用户的配置自动决定站点，跨站不用改代码。
2. **判据：这份配置本来就在用户手里吗？** 在 ⇒ 推导；不在 ⇒ 才需要固定值（并标注未核实）。
3. **「不内置」不等于「不给出路」** ⇒ 本片同时给了 `baseUrlV2` 显式覆盖口，
   让代理/网关这类「非同域」场景也有路可走。

### lesson: adapter-signature-must-match-the-repo-wide-call-contract

**现场**：`callAdapter` 统一以**一个对象**（`{ videoId, taskId }`）调用适配器方法，
而 `adapters/minimax.js` 的 `getVideoStatus(taskId)` 要**字符串** ⇒
经生产调用链会把对象拼进 URL（`task_id=%5Bobject%20Object%5D`）⇒ **轮询必然失败**。
而同一仓内 `agnes-video.js` 早已按对象形态写好（还留了一句人写的注释）⇒ 本文件是**漏改**。

**根因**：**「适配器方法收什么」这条契约没有机械判据** ⇒ 每家适配器各自落地、各自漂移；
测试又只喂字符串形态 ⇒ 对象形态那一格**从未被构造** ⇒ CI 全绿下活了下来。

**可复用的 3 条**：

1. **仓内契约一旦统一，就该有**一处**实现 + 一处**断言**；散落在各适配器里的同款逻辑
   （哪怕写法一致）也是**没有判据的多份实现**。
2. **新写适配器时，先 grep 同一仓内**已按该契约实现的适配器**（本例是 `agnes-video.js`）⇒
   照抄它的写法，而不是自己发明第二种。
3. **「人写的注释」不是判据** ⇒ 那句注释只提醒当时的人，不拦后来的人。
   ⇒ 要真拦，就得写成用例（对象形态 + 断言 URL 里不出现 `object`）。
