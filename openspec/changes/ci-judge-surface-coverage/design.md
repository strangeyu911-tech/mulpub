# 设计：高危面由判据闭包派生

> ⚠ 本文第一版（同一天的初稿）写的是"把 5 个文件按名字加进 `HIGH_RISK_SURFACES`"。
> 该设计被自己的取证否证，现整体改写为**闭包派生**。否证过程留在 D1，因为它就是本片存在的理由。

## D1 为什么从"按名增补"翻成"闭包派生"（本片的立项证据同时否证了第一版）

按名字补清单的两个死法：
- **会长回来**：`HIGH_RISK_SURFACES` 里 `scripts/lib/ccg-review-` 那条的 `why` 原文写着
  「跨家族轴 X2-9 实测这条此前落在清单外，改它不触发任何收口要求」⇒ 上一轮就是这么补了一格，
  本轮又数出 19 格。**补名字只解决"已经看见的这几个"，不解决"还会再漏"。**
- **默认方向错了**：按名增补的隐含默认是"新文件不算高危面"。而这类清单的正确默认必须是
  "**新文件默认算，想不算要写理由**" —— 与 `KNOWN_UNWIRED` / `doc-abs-paths-baseline`
  的"承认清单起始为空、只能缩小"同一条口径。

翻过来之后，"分类"这个动作从**每个新判据文件都要有人记得做**变成**没人做就红**：
闭包成员自动进面，人只在想降级时才需要判断。

## D2 闭包定义（窄、可复算、边界如实）

- 入口集：`scripts/` 下 basename 匹配 `^check-` / `^ccg-review-` / `^deep-review` 的 `.js` / `.sh`，
  **排除 `*.test.*`**。第一版探针没排测试，把 `check-x.test.js` 当入口 ⇒ 入口数虚报成 90、
  闭包虚报 113、并把 `ccg-test-helpers.js`（测试夹具）拖进分类域。
  这条不是修辞：**测试可达性混进生产分类域**正是本片要防的那一格的自身版本。
- 只跟**字面量相对 `require`**（`./` / `../`）。动态拼接看不见 ⇒ 该边界必须打在输出里，
  不得宣称"完整覆盖"。当前实测这类 require 数量为 0；"当前为 0"≠"永远为 0"。
- 不跟进测试文件（既不作为节点展开，也不因被测试 require 而进面）。这条同时解决
  "helper 哪天被生产 require 了怎么办"：**不需要维护名单**，闭包每次重算，翻面那天它自己进来、锁自己红。
- **规模下界**：入口数 / 闭包数 / lib 数各自断言下限。解析退化会让"零违规"与"什么都没扫出来"
  逐字同形，那是一条恒绿门禁的标准死法。

## D3 判据侧（`check-pr-exec-record.js`）怎么吃这个派生面

`isHighRiskSurface(rel)` = 原前缀命中 **或**（`rel ∈ 闭包` 且 `rel ∉ 豁免`）。三条不可破：

1. **算不出闭包 ⇒ `selfFault`（未证实），不是"不在高危面"**。与本文件既有
   `后端清单取不到读数` 同一档：把工具的失明读成"这条不需要外部复核"是本仓定性过的装饰性门禁。
2. 一次 PR 判定内**只算一次闭包**（注入式：`makeJudgeClosure(repo)` 返回带缓存的对象），
   不得在每个文件上重复走图 —— 这是第二份遍历、也是性能地雷。
3. 豁免清单由 `scripts/judge-surface-waivers.json` 单点持有，**只有派生判据读它**；
   `HIGH_RISK_SURFACES` 常量与 `why` 文案不改写（它仍是"按路径形状承认的面"）。

## D4 豁免清单：登记项起始为空、只能缩小，上限只能由人工改，每条必须带 reason

`{}` 起步（本片实测**不需要**任何豁免：19 个漏网文件按 D5 的规则逐条看，都属"改了就改变谁红谁绿"）。
四条硬判据由 `check-judge-surface-coverage.js` 强制：值必须是非空字符串；条数 `<= 0`（上限常量，
抬起属人工裁决）；键必须仍在闭包内（陈旧即红）；闭包外文件不得被豁免（那是在给不存在的东西发许可证）。

⚠ 措辞精度（QM-6 轮 3 i3，**upheld 后当场清偿**，不留到"以后再说"）：**「只能缩小」的主语是登记项，不是上限常量**。
上限为 0 时说"上限只能缩小"没有意义（缩到负数不是通道），而混在一句里会让读者以为存在一条"先加进来再缩回去"的路径。
正确读法两条分开：**登记项集合**只能缩小（陈旧键必须删、闭包外的键不发免检牌、当前必须为空）；**上限常量** `MAX_WAIVERS` 只能由人改代码来抬，改它就是在放宽「谁来守门」。（同族 i5 的驳回不受影响：它驳的是"实现与设计文档冲突"，这条修的是我句子里的主语。）

## D5 什么算"判定逻辑"（用于事后核查，不作为自动判据）

口径：**该文件的逻辑出错时，会不会直接改变某条判据的红/绿结论**。
`code-mask.js`（决定扫描器看得见什么）会；`merge-ledger.js`（决定收口归属）会；
`image-mime.js`（不在闭包内，也不被任何 `check-*` require）不会。
这条**故意不做成自动判据**（AGENTS 对"从源码提字面量求交集"的启发式判据有明文否证先例），
它只是人写/审 reason 时的依据。

## D6 空转条目锁（防"登记了但永不命中"）

`HIGH_RISK_SURFACES` 每条按其自带口径（`prefix` 或 `fingerprint` 的 `exts`）对全仓受管文件求命中，
命中 0 ⇒ 红并点名该条。为什么必须有：那些条目的 `why` 里写着"实测命中 N 个"，
**N 是登记当天的数**；文件搬家或前缀手误之后，它会继续躺在那里像证据，而门禁恒绿。
`fingerprint` 那条必须复用它自己的 `exts` 限定，用裸前缀比会让它永远命中 0（红的是判据自己）。

## D7 摩擦如实报（不假装没有代价）

按当前闭包，19 个文件立即成为高危面成员 ⇒ 改 `code-mask.js` 这类 PR 也纳入收口矩阵。
接受的理由：① 与 `scripts/check-` 已覆盖 106 个文件同源（都是"改了会改变谁红谁绿"）；
② 双模型时长由 decider 的 mode 决定（小 diff 判 `single`），所以这一刀主要收紧**可见性**而非时长；
③ 若某个 lib 被证明确实与判定无关，走 D4 的豁免出口并写 reason —— 代价是一次显式的人工动作，
而不是今天的静默漏网。
④ 但这句"时长几乎不变"依赖 8.5 那格未修（`single` 不需要闭环记录）——
**不得把 ② 当成本片已解决摩擦问题**，它同时是本片效果的一个已知折扣，见 D8。

## D8 已知不闭合（登记，不装作已闭合）

1. 8.5：小 diff 被判 `single` ⇒ 不要求闭环记录 ⇒ 本片让"哪些文件算高危面"变可见，
   但**没有**让"每次改判据都必须外部复核"成立。修法会把 23–40 分钟钩子时长加到每次改判据上，
   属「谁来守门」，须人工单独裁决。
2. 动态拼接的 require 看不见（D2）。
3. GitHub 侧 required check 清单在平台侧、仓内无对账面。
4. （QM-6 轮 1 i1 副产，当场读数）`ccg-review-decider.js` 的 `stats.changedLines` 与 numstat 不是同一个量，且产物里不写它是**哪个采集路径**算出来的（实测同一 PR：产物 1202 / numstat 1751 / diff 文本行数 2084）。同一次读数还暴露 `sensitivePathHits=[]` 而差量含 3 个 `scripts/check-*` ⇒ 两份清单（decider 的 RULES.sensitivePaths 与 本判据的 HIGH_RISK_SURFACES）确实互不认账。修法属"改谁来判规模与敏感面"，须人工过目，不在本片顺手改。
4. 若将来某次改动让闭包显著变大（例如把 `apps/desktop/electron` 的判据也 require 进来），
   规模下界会红而不是静默膨胀 —— 这是设计意图，但**上限**没有锁（防不住"越收越宽"的反方向），
   因为方向相反：闭包变大意味着更多代码被要求外部复核，属收紧，由人抽查。

## D20 实现期被实测推翻的两处设计（原设计是"只跟字面量、注释不处理"）

| # | 设计期写的 | 实测到的 | 处置 |
|---|---|---|---|
| 1 | 「只跟字面量相对 `require`；动态拼接看不见，**当前实测为 0**」 | 分段字面量的 `require(path.join(__dirname, 'lib', 'x.js'))` 在静态上**就是可定的**，而 `scripts/lib/gate-timeout-registry.js`（每条 gate 的超时预算登记，`check-coverage-budget.js` 唯一入边）正是只被这种写法引用 ⇒ 设计期的"看不见"里混进了一半"没去看"。真·变量参数（`require(f)` / `require(path.join(root, …))`）当场 **6 处**，不是 0 | 收进闭包：`classifyJoinRequires` 只在「除 `__dirname` 外全是相对字面量」时拼装；混进别的变量一律退回 `dynamic` 账（不得假装能）。`unresolved` 由 3→0，`files` 由 67→69，`derived-only` 由 19→21。**"当前为 0"那句从未实测，按本仓口径改写为当场读数** |
| 2 | 未想过注释行 | 第一跑 `unresolved=3`：`scripts\$REC`、`scripts\lib\x`、`scripts\z.js` —— 三条**全部**来自散文里的示例写法 | 按整行剥注释（替换成等长空格以保持字符偏移），于是 `unresolved>0` 从恒噪声变成一条真会指到漏网的判据；`dynamic` 也不再被自家注释里的 `require(prefix + name)` 顶高 |

两条的共同形状：**设计期把"我没看见"写成了"它不存在"**。这与 `rebuttals-in-review-adjudication-must-be-measured`
同族 —— 区别只是这次是被自己第一跑的读数抓到，而不是被评审抓到。

## D21 接线期的两处既有面迁移（不得读成"顺手放宽了旧锁"）

1. **两条结构锁的锚点随签名迁移**：`highRiskPrefixOf(file)` → `highRiskPrefixOf(file, judgeSurface)` 之后，
   `X2-5③` 与 `2.1 单一匹配实现` 的锚点必然落空。改法是**跟着新形态改锚并加严**：
   `X2-5③` 新增「main 必须造上下文、构造点唯一、且排在债务判据之前」+「债务判据自带兜底构造」两条断言。
   判据：改锚之后新锁必须能抓住"把参数丢掉"这一变异（M11），否则它只是被我自己的改动打红过一次的噪声。
2. **16 处临时仓夹具 seed `scripts/`**：`evaluateDeepReviewDebt` 在调用方不注入时**自己建**上下文（fail-closed），
   于是没有 `scripts/` 的临时目录会得到 `selfFault` —— 那是对的出声，但那批既有用例量的就成了"这个目录不是仓"，
   而不是"这篇产物收口成不成立"。按 AGENTS「① 夹具该更像真实形态 ⇒ 把环境造成那个形态，别改断言」处理：
   seed 的是 `scripts/lib/seed-noop.js`（**非**判据入口），只建立"这是个仓"这一前提，
   不给任何既有用例新增一条派生面命中。反例锁由 `check-pr-exec-record-judge-surface.test.js` 的
   「真实仓根之外没有 scripts/ 的目录必须报 selfFault」那条守住 —— 没有它，seed 会被读成"闸门被关掉了"。

## D25 采纳 i4 之后自己引入的第二颗雷（由读数的意外变化抓到，不是由评审抓到）

轮 2 i4 修完（按文件跟踪块注释状态）之后，我照例重取一遍读数，发现 `dynamic` 从 **6 变成 5**。
一句"少了 1"没被当噪声吃掉，逐行复算抓到的却是**我自己的修复引入的假阴性**：

- `scripts/deep-review.sh:386` 是 shell 的 `case` 分支 `/*)`，第 41 行是参数展开 `${_self_dir%/*}`；
- 块注释状态机把它们当 `/*` 起点 ⇒ 从第 386 行起整个文件被读成"在块注释里"，
  直到第 620 行那句真代码 `try { r = require(f); } catch (e) {` 被整行抹白；
- 后果不是"少计一个 dynamic"，而是**同一套剥离会让 shell 里任何真依赖静默消失** ——
  方向与本刀要消灭的东西相反（那是放行侧的失明，不是保守侧的过拦）。

处置：注释规则**按语言分档**（`JS_EXT_RE`）——只有 `.js/.mjs/.cjs/.jsx/.ts` 才用整行 `//`·`*`、
行内 `//`、跨行 `/* *\/`；`.sh`/`.ps1` 只认整行 `#`，行内与块都不猜。
两条回归锁：`shell 文件里的 %/* 与 // MUST NOT 被当块注释`（用 386/41 两行的真实形态做夹具）+
`规则按语言分档`（JS 块内不算、块后必算、shell 行内 `//` 不猜）；变异 M16 摘掉分档必须指名红。
量到的现状：`dynamic` 回到 **6**、`files=69`、`unresolved=0`。

**可复用的口径（本刀的第三条）**：
1. 修完一条评审意见后**必须重取全部相关读数**，并把与修复前不同的每一个数解释掉。
   这次如果只跑"新增用例通过"就交付，`dynamic=5` 会作为新基线被写进文档，
   而下一个人看到的"闭包里没有 shell 依赖"就是我造的假象。
2. **启发式剥离必须按语言给范围**：注释语法是语言属性，不是"文本里长得像注释"。
   判据写成人话就是——问"这一行在**这个语言**里是注释吗"，不要问"它看起来像不像注释"。
3. 同族的第二次提醒（轮 1 i3 → 行内、轮 2 i4 → 跨行、本轮自查 → 跨语言）：
   每一次"把噪声剥掉"都在扩大剥离器的权力，而剥离器的过度剥离**没有任何下游会红**。
   所以剥离器每次扩展都必须自带一条"真依赖仍被抓到"的正控，而不只有"假依赖被剥掉"的负控。

## D26 QM-6 实现轴轮 3（HEAD `11d369272`，交付 8 条 / 最低维分 4）与"三轮到顶"的实际处理

轮 3 复用存档 critique 与已填裁决（引擎打印 `♻ 复用存档 critique（8 条）+ 已填完的裁决 —— 跳过模型调用`），
7 条待裁决全部填完，verdict 分布 **6 dismissed + 1 upheld**。逐条正文与读数已在 PR #4486 的公开评论里留痕
（`https://github.com/Colinchiu007/mulpub/pull/4486#issuecomment-6409748508`）。

**那条 upheld 是什么、为什么必须当场修**：i3 指的不是实现，是我自己句子的主语——我把「上限常量只能由人工改」
和「登记项只能缩小」压成了一句「豁免清单起始为空、只能缩小」。上限 `=0` 时说它"只能缩小"是无意义的，
而这句话会让读者以为存在一条"先加进来再缩回去"的通道。实现没有问题（`MAX_WAIVERS` 定义 1 处 + 导出 1 处 + 消费 3 处，
无第二份事实），所以**修法是把主语拆开**：AGENTS 该条、design D4、spec 的 Requirement 标题与上限句同时改准。

两条纪律在这里撞到一起，取的是贵的那一边：

1. 「自用三轮到顶就交人工」——它限制的是**为了追一个绿灯而反复重评**，不授权"把已认账的缺陷推到以后"。
2. 「盖章之后动被评审的差量会作废章」——所以清偿必须**在签字之前**做完；先签再改文档，改的就是别人已经核过的那份。

约 15–25 分钟。这个代价是"认账"的价格，不是流程缺陷；若为省它把 i3 改成 dismissed，就是在含已知缺陷的 critique 上说谎。

PR 评论里那条「采纳但不在本 PR 清偿」的表述**已被本行取代**（当时按"三轮到顶"选的处置，实测与"不得留 upheld"冲突）。

## D27 两份手抄的 require 闭包清单：第二次踩中、配方、以及为什么不在本片收敛

**现场**：本片给判据本体 `check-pr-exec-record.js` 加了一条新的本地依赖（`lib/judge-closure.js`）。
两份临时仓夹具的 require 清单都是手抄的，于是同一条依赖边各漏一次：

| 清单 | 宿主 | 承认判据 | 漏抄时的形态 |
| --- | --- | --- | --- |
| `SCRIPT_CLOSURE` | `deep-review-entry-rc.test.js` | 守卫 ⑫ 扫「被复制脚本自身的相对引用」，**剥注释后**再扫 | CI Gate 2b11 整批同形失败（临时仓加载期就崩） |
| `ENTRY_WRITEBACK_CLOSURE_B` | `deep-review-deps.test.js` | i3 锁从写回器入口沿引用图 BFS 求闭包 | CI Gate 2b 一条指名红，文案直接点名缺哪一项 |

第一次（run `40282111456`）我给的归因是"本机预跑清单没含本文件"。那句只解释了**为什么本地没抓到**，
没解释**为什么会漏**——归因不完整，所以第二轮 CI 红时它被补上了：真实成因是同一条依赖边有**两份手抄承认面**，
而补的人只看得见自己刚跑过的那把锁。

**收敛配方**（下一刀该做的形状，写在这里是为了让它可被重取而不是靠记忆）：把清单落成
`scripts/lib/deep-review-fixture-closure.js` 的单一导出（按用途给两个具名数组，差异如实留在同一处），
两份测试各自 require 它；i3 锁的判据随之从"这份清单 ⊇ 推出来的闭包"升级为"那份唯一导出 ⊇ 推出来的闭包"，
并补一条接线锁：两份测试文件里不得再出现各自的字面清单数组。

**顺带一条脆弱前提（收敛那一刀应一并处理）**：i3 锁**不剥注释**，所以注释里的示例写法会进闭包。
当场读数里就有两条假边（一个占位名与一个夹具名），它们目前只因为"磁盘上不存在那个无扩展名的路径"
才被 `missing` 过滤放行。也就是说：**今天往 `scripts/lib/` 建一个与注释里举例同名的真文件，这条锁会当场假红。**
收敛时应让 i3 与守卫 ⑫ 共用同一个"剥注释后再扫"的实现——这也正是本片把剥注释收进单一真源的同一条理由。

**为什么不在本片做**：本片的评审域是「高危面由判据 require 闭包派生」，这一格改的是**另一条链的测试夹具**。
把它扩进来的价格不是行数，是**已盖章的第 4 轮评审会随内容寻址键一起作废**（换差量即换键，下一轮要真调模型），
而 QM-6 的靶子会与被修的东西脱节。所以本片只落两处：给第二份清单补同一项、并把"这是第二次踩"写进该项的注释与本节；
收敛作为具名欠账登记在 `未闭合清单`。
