# 跨档压制的计价与生效模型（订阅段链）

## 1. 问题

pro 用户兑换「standard 365 天」激活码之后，低档权益应该**排队、生效、计价**。

现状（`packages/api-publish-engine/src/auth/postgres-commerce-store.js` @ main `a87d2d713`）：

- `:112-116` `downgradeSuppressed`：已有档位 rank 严格高于请求档位 ⇒ 保现有档位（**只压档位**）。
- `:130` / `:133` `base` / `periodEnd`：`base = 现有 current_period_end`，`periodEnd = base + durationDays`
  ⇒ **时长无条件直加**。

合起来：**pro 用户兑一张 standard 365 天码 ⇒ 订阅行仍是 pro、有效期 +365 天**
⇒ 一张 ¥590 的码交付了 ¥1190 的 pro 权益（**2 倍套利**）。

而 `01-docs/PRD-REDEEM-CODE-ISSUED-TO-2026-10-24.md` §16 第 1 项把这条记成「待拍板」，
且原括注「standard 码只值 30 天」**在仓里没有任何对应机制**（无折算表、无换算函数）。

## 2. 定案

**订阅段链**：订阅 = 一条由若干「段」首尾相接组成的时间轴，每段自带「档位 × 时长」；
**档位 + 时长 = 面值**。低档码**排队兜底**（等当前档位走完后以自己的档位生效），不折算、不延长高档。

⇒ 套利**在结构上不可能**（不靠一张会漂移的折算表去堵）。

模型全文：`01-docs/PRD-SUBSCRIPTION-SEGMENTS-2026-10-25.md`（新）。

跨档挤位规则（R1 高档抢占 / R2 同档续叠 / R3 低档排队 / R4 冷启动）、
结算推进惰性钩子点、新表 DDL、过期判定逐处迁移清单（M1–M7）、
数据校验 10 条、验收判据 18 条（机械）+ 3 条（人工）、文案 8 条、分片落地清单 S1–S5，
全部在该 PRD 内。

**顺带修掉的存量缺陷**：高档码抢占时现状会**丢弃旧档位的剩余时长**
（`UPSERT_SUBSCRIPTION` 是 `ON CONFLICT DO UPDATE SET plan/period` 整段覆盖，非接续）
⇒ 段链模型下旧段顺延保留（PRD §1.2 / §2.3 R1）。

## learnings

### lesson: 一次「按时长加长」的实现会把低档码变成高档延期券

**现场**：会员系统里激活码核销走「`periodEnd = 现有到期时刻 + durationDays`」，
而档位保护只在「请求档位更低」时保留旧档位 ⇒ **时长不降级、档位才降级**
⇒ 一张 standard 码在 pro 账号上变成了 pro 的延期券。

**根因**：把「时长」当成了唯一的面值维度，**档位被当成了可降级的元数据**。
一旦时长可以按面值无限叠加，面值与档位就脱钩了。

**可复用的 N 条**：

1. **「时长」与「面值」必须解耦，且必须有一处显式写死「面值 = 档位 × 时长」**——
   否则任何「按剩余时长加 N 天」的写法都会变成跨档套利通道。
2. **档位保护只保护档位、不保护时长，是半个保护** ⇒ 审查这类实现时要问
   「低档位输入在**时长**上被降级了吗」，而不只看「plan 字段有没有被改」。
3. **这类缺陷的敞口随「码的售价 vs 生效档位价值」线性放大** ⇒ 签发端的天数上限
   （本仓 3650 天）本身就是敞口放大器，不能与档位闸分开看。
