## 接管修正：一次自伤的复盘（QM-5 五步）

> 本节是**接管轮**加的。前一版记录里有一整节叫「顺带修掉的主干自红」，
> 描述的是一个**不存在的现象**（那节已被本节按事实重写）。

### 事实（一手可复现）

中途一版提交（`b68ab7e`）把仓里 **12 篇不属于本 PR 的执行记录**的 frontmatter 字段
`delivered_by_pr` 统一从「各自原始 PR 号」改成了 `4408`，理由写得很完整：
「主干自红 ⇒ 这 12 篇是被 #4408 夹带进主干的 ⇒ 声明值应改成 4408」。

**该理由在事实层面不成立**（三条独立取证）：

| # | 取证 | 读数 | 结论 |
|---|---|---|---|
| 1 | `git show 7c97f1f --name-only \| grep openspec/records` | **空** | #4408 只改了 4 个文件（`docs/ops-center-ecs-deployment.md` + `openspec/changes/official-keys-postgres-migration/{design,proposal,review-responses}.md`）⇒ **它从未把任何执行记录带进主干** |
| 2 | `scripts/lib/merge-ledger.js` 的 `addedBy`（账本唯一真源），baseRef 取 `7c97f1f` 与 `origin/main` 两个点 | 12 个路径的归属 = `4342 / 4343 / 4343 / 4108 / 4248 / 4140 / 4062 / 4194 / 4092 / 4345 / 4224 / 4235` | 与主干上各文件**原本的声明逐字相同** ⇒ 主干本就是自洽的 |
| 3 | 干净检出复跑 `node scripts/check-gate-record-debt.js`（`origin/main`@`071318d31` 与 `7c97f1f` 两个点） | **rc=0 绿**，输出里**没有**「声明的来源 PR 与主干事实不符」 | 所谓「主干自红」**不存在** |

⇒ 真因是**自己**：把 12 个原本正确的声明改成 `4408` 之后，`declared=4408` 与
`actual=4342…` 逐篇不符 ⇒ `intentMismatch` 12 条 ⇒ 门禁判红 ⇒ `QG Changes` 红 ⇒ `Gate Result` 连坐红。

### QM-5 ① 第一性原因

**判据判对了，判红是正确行为；错在「拿到判据的读数之后又自己造了一份推断」。**

- 门禁的输出**本来就印着真值**：`xhs-draft-store.md —— 声明 4408 / 实际带入 4235`
  （`实际带入 X` = `merge-ledger.addedBy` 的取值）。
  但那一轮**没有采用它**，改用 `git log --diff-filter=A` 二次推断，得出**相反**的结论。
- 三个偏差叠在一起：
  ① **没读输出里的真值** ⇒ ② **另起一份口径**（两套口径必然漂移，且漂向「支持我已有的结论」）
  ⇒ ③ **错误结论被写成了文档**（commit message + 执行记录整节正文）⇒ 看起来像有据可依。

### QM-5 ② 逃逸分析

| 层 | 发生了什么 | 为什么没拦住 |
|---|---|---|
| 判据 | 正确判红，位置也对 | — |
| CI | 红在正确的作业（`QG Changes`） | — |
| 取证 | 没读输出里的真值，另起 `git log` 推断 ⇒ 结论与真值相反 | 门禁的**输出格式没有主人** ⇒ 真值「在场但无人拥有」 |

⇒ **当复现结果与自己的预期一致时，反而要再验一次它是不是恒真。**

**关键设计取舍**（详细版见 PRD §15）：

- XFF 取**最右**（nginx `$proxy_add_x_forwarded_for` 把真实 IP 追加到末尾）⇒ 客户端自带的伪造值在左端被忽略，
  甩不到别人头上；直连时 XFF 可伪造是**有意取舍**（生产必然经反代，引擎只绑回环）。
- 桶被逐出时计数**归零** ⇒ 该身份「多几次机会」，**不是**「绕过限流」⇒ 可接受
  （限流器是安全阀，不是安全边界）；一次逐出超出量 ⇒ 摊还 O(1)。
- 迁移正则**不放宽**（`\d{3,}` 会让 `1000_x.sql` 排在 `999_x.sql` **之前** ⇒ 有 FK 时建表顺序错乱）
  ⇒ 宁可启动失败，也不要静默少执行一条迁移。
- 桌面端**不自动纠正**易混淆字符（`I`/`L`/`O`/`0`/`1`）⇒ 悄悄改会让用户以为输对了、兑换时才发现不对
  ⇒ 保留原样交给本地校验去拒，并给出可读原因。
- 运营端 CSV 的列来源是**签发结果**而不是当前表单（结果弹窗打开时表单可能已改过）
  ⇒ 用表单值会导出一张「看起来对、其实不是这批码」的表。

## learnings

### lesson: 判据的输出里往往已经印着真值，不要另起一套推断（redeem-next-round）

**现场**：门禁判红并逐篇印出 `xhs-draft-store.md —— 声明 4408 / 实际带入 4235`。
那一轮改动**没有采用这个值**，改用 `git log --diff-filter=A` 二次推断，得出「实际带入 4408」
的**相反**结论 ⇒ 把 12 篇别人 PR 的执行记录改了 ⇒ 门禁当场判红。

**可复用的 N 条**：

1. **判据输出 = 真源的第一现场**。要改任何由判据管理的值 ⇒ 先把输出里的**真值抄下来**，
   绝不另起第二份口径。⇒ 而且**输出格式本身要有人拥有**（没有主人 = 随时可能被改成「只列文件名」）。
2. **「主干自红 / 别人夹带了」是可被反驳的强主张**。要据此改动**非自己新建**的文件，
   必须附**取证三件套**（干净检出的 SHA + 复现命令 + 原始输出）。
3. **git 归因要读「加了 A 事件的那次提交」**，不是「最近一次触碰」、也不是「看起来相关的那次合并」。
   实测：`git show <sha> --name-only` 里根本没有目标路径 ⇒ 那次合并从未夹带过它们。

### lesson: 本地复跑与 CI 结论冲突时，先查差异来源（redeem-next-round）

**现场**：本地打印 `intentMismatch: []`、CI 报 12 条。那个矛盾**本身就是「本地复跑方法有问题」的信号**，
却被当成了「本地对、CI 错」⇒ 用本地结果否定 CI。

**可复用的 N 条**：

1. **冲突时默认「复现方法有差异」，不是「CI 错了」**。先对齐三个量：**baseRef SHA、工作树内容、判据版本**。
2. **复跑必须钉死 baseRef**（`git rev-parse origin/main` 取到具体 SHA 后写进命令），主干在会话进行中会前进。
3. ⇒ **拿 CI 的读数当线索，不当权威**。权威是「在 CI 的确切条件下能不能复现出同样读数」。
4. ⚠️ **当复现结果与自己的预期一致时，反而要再验一次它是不是恒真** ——
   那个「空」当时恰好符合作者已想好的结论，于是没被当成异常。

### lesson: 同一语义在仓里出现两处时，必须收敛到单一真源（redeem-next-round）

**现场**：Mulpub 的「激活码兑换」功能在第 3 轮对抗性审查里被查出：兑换限流按
`X-Forwarded-For` 最右分桶，而全局粗桶按 `req.socket.remoteAddress` 分桶；
生产拓扑是 nginx → `127.0.0.1:3030`、引擎只绑回环 ⇒ 粗桶看到的来源恒为 `127.0.0.1`
⇒ **全站所有用户共用一个桶**，而兑换限流那套精细口径**根本轮不到**。

**根因**：两处实现各自演进，没人意识到它们描述的是**同一个语义**（客户端身份）。
测试也只覆盖了「限流器怎么算」，没覆盖「**谁**的分桶键」。

**可复用的 N 条**：

1. 任何「按客户端身份 / 按租户 / 按来源」分桶的机制，**取值口径必须与真实拓扑对齐**
   （反代后面看到的是回环地址，不是客户端）。
2. 同一语义在仓里出现两处 ⇒ 抽成**单一真源**（本次抽 `src/client-ip.js`），
   否则下次又会长出口径分裂，而且**哪一处生效取决于调用顺序**。
3. 变异/审查要问「**这个键是谁决定的**」，而不只是「这个算法算得对不对」。
