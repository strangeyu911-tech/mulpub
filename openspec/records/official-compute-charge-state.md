## learnings

### lesson: client-reported-identity-must-never-drive-billing

**形态**：一个「用量上报」端点只有静态服务 key 鉴权 ⇒ 请求体里的 `user_id` 是**客户端自称**的。
若服务端拿它去扣分 ⇒ 恶意客户端上报别人的 `sub` ⇒ **扣别人的积分**。

**判据（三条）**：
1. ⭐ **凡是「客户端上报的标识」被用于「向谁收钱」，先问「这个标识被服务端验证过吗」**——
   没有验证 ⇒ 它是**输入**不是**身份**。
2. ⭐ **缺省必须落在安全侧**：标记的默认值要选「不收钱」而不是「收钱」⇒ 忘写 = 不扣，而不是扣错人。
3. ⭐ **判定要放在服务端的一个纯函数里**（可单测、可复用）⇒ 客户端**绕不过**它；
   散在业务流程里的判定迟早被新入口复制一份 ⇒ 分叉。

**泛化**：任何「上报 → 记账/发券/限流」的链路，标识的**可信度**必须与它的**用途**分开评估。

### lesson: write-a-mechanism-only-when-its-input-exists

**形态**：补扣执行体 = 读 `pending` 事件 → 调扣分端点。看起来是「还差一个执行体」，
但当前 `pending` **恒为空**（客户端身份不可信 ⇒ 全部不可计费）⇒ 写出来是**恒空转的死代码**。

**判据**：
1. ⭐ **写一个机制之前先问「它的输入现在有吗」**——没有输入的机制 = 纯空转
   （与「等一段时间再重试」必须有**随时间变化的恢复信号**同族）。
2. ⭐ **「缺一个组件」不等于「该现在补」**⇒ 要区分「**缺输入**」与「**缺实现**」：
   缺输入时补实现 = 把空转写进代码，且制造「已完成」的错觉。
3. ⇒ 本刀的选择：**把数据面与判定做完、把执行体与宿主留空**，并在执行记录里写明
   「真正的前置是 D-① 代理落地（或平台签名凭证落地）」。

### lesson: a-criterion-reading-the-code-under-test-is-self-referential

**形态**：迁移测试断言「被测代码的补列清单里的列都在表里」⇒ 变异「清单少补一列」**没被抓住**
⇒ 因为清单少一列、断言也跟着少查一列 ⇒ **永远绿**。

**判据**：
1. ⭐ **判据侧必须有一份自己的期望值**（字面清单），并额外断言「被测清单 == 判据期望」
   ⇒ 改实现必须同步改判据，**改不动判据就红**。
2. ⭐ 与既有纪律同源（「判据要有自己的一份实现」「相对断言恒真」）⇒ 每次写完锁都问：
   **「我这条断言的期望值，是从被测代码里读出来的吗？」**

### lesson: git-history-derived-gate-readings-drift-when-the-clone-is-shallow

**形态**：门禁用 `git log <base> --diff-filter=A` 推导「这份执行记录是被哪个 PR 带进主干的」，
口径是**最近一次新增**。本地克隆浅（depth=25）⇒ 浅历史里的「最近一次新增」落在一个**更晚**的提交上
⇒ 本地账本给出的归属与 CI（`fetch-depth: 0` 全历史）**不同**，而两边 base tip 完全一样。

**后果（本次实测）**：据此把 12 篇记录的来源 PR 统一改成一个值 ⇒ 本地门禁全绿 ⇒ CI 逐条印出真值后立刻红。
⇒ 错的那次已经进了提交信息 ⇒ 只能再开一笔**如实披露的撤销**（不改写历史）。

**判据（可复用的四条）**：
1. ⭐ **判任何「基于 git 历史的门禁读数」之前，先确认本地历史深度与 CI 同源**：
   `git rev-parse --is-shallow-repository` ＋ `git rev-list --count <base>`。
   本次读到 `true` 与 `25`（真实提交数是几千）⇒ 口径**已不同源** ⇒ 读数不可作为事实。
2. ⭐ **「本地绿 ⇒ CI 也绿」在这类门禁上不成立** ⇒ 历史型/差量型门禁**必须**在 CI 的历史深度下复跑才算数。
3. ⭐ **门禁输出里逐篇印出的真值就是权威**：CI 印「声明 4421 / 实际带入 4235」时，
   正确读法是「**实际归属是 4235**」，不是「我的 4421 被谁覆盖了」。
4. ⚠ **「主干级存量红」是强主张** ⇒ 断言它之前必须附「在哪个 SHA 的**干净检出**上、用**与 CI 相同的历史深度**复现」。
   本次缺了第二件 ⇒ 差点把一个**不存在的存量红**写进提交信息与 PR 正文。

**泛化**：任何用 `git log` 推导归属/增量的门禁，在浅克隆环境里都会漂移；
⇒ 判「主干红不红」之前，先 `git fetch --unshallow` 把历史补全。
