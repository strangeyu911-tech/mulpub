## 0. 结论速览（TL;DR）

### 0.1 五句话

1. **三档**：免费版 ¥0 / 标准版 ¥59·月（¥590·年）/ 专业版 ¥119·月（¥1190·年）。年付一律「月付 × 10」，即 16.7% 折扣，不设第二套年付权益。
2. **双轴**：额度轴（平台数、发布量、并发、设备、云账号、AI 额度）+ 功能轴（自动化、产出质量、商业化授权、治理）。只有量变的升档是最弱升档理由，每档相对下一档至少解锁一个「质变」。
3. **五层权益栈**：L1 平台能力 / L2 工作流自动化 / L3 产出质量 / L4 商业化 / L5 治理。档位差异按这五层排布，不按功能菜单罗列。
4. **当前执行面只有两条半**：云 API 的 `batch_size_per_run`（1/10/不限）和 `cloud_publish_monthly`（150/1500/30000）是**服务端硬门禁**；桌面发布页的 `max_platforms`（5/15/不限）只是**客户端软提示**。其余额度与 feature 已下发但**没有消费点**，详见 §7。
5. **不新增团队档**：产品没有多用户体系（无席位、邀请、角色、审批、SSO），现在加团队档就是超卖。未来若做，至少要先定义席位、共享积分池、审批流、审计、SSO 五项。

## 1. 档位定位与边界

### 1.1 三句话定位

| 档位 | 一句话 | 目标用户 | 核心升级理由 | 明确不包含 |
|---|---|---|---|---|
| **免费版** | 先拿两个号试试，跑得通再放大 | 个人新手、单平台创作者、尝鲜者 | 零成本验证「多平台发布」是否省时间 | 视频生成、定时发布、云同步、批量、完整看板、多设备 |
| **标准版** | 日更五平台的全自动工作台 | 一人公司、个人 IP、2–3 人小团队 | 定时 + 批量 + 云同步 + 视频额度，把「手动日更」变成「排期后不管」 | 平台不限、模型高阶、4K、API、团队席位 |
| **专业版** | 矩阵号的产能与合规天花板 | 多账号矩阵、代运营、工作室 | 平台不限 + 日发 1000 + 并发 10 + 设备不限 + 高阶模型，撑住「几十个号同时跑」 | 团队席位、SSO、完整白标、专属 SLA |

### 1.2 为什么是三档，不是四档

- **行业主流是四档**（免费 + 入门 + 专业 + 团队/企业，15 个样本里 9 个如此），但第四档全部由「团队协作 + 安全合规 + SLA」支撑。
- 本项目**没有多用户模型**：没有席位、邀请、角色、审批、共享积分池、SSO、审计日志。现在卖「团队版」只能卖「同一账号多设备」，销售一定会把它讲成「多人协作」，交付时必然翻车。
- 因此第四档**只预留、不发布**。触发条件（任一满足才立项）：① 出现 ≥3 个真实客户要求「多人登录同一工作区」；② 代运营客户要求「子账号只看到被分配的账号」；③ 企业采购要求 SSO/审计。立项时必须先定义五件事：席位模型、共享积分池、审批流、审计日志、SSO。

### 1.3 销售禁用词（硬约束）

| 禁用说法 | 为什么禁用 | 可以说 |
|---|---|---|
| 「专业版无限发布」 | 专业版是 1000 条/日，不是无限 | 「专业版日发上限 1000 条」 |
| 「标准版 AI 写稿不限量」 | 不限的前提是**走自有 Key（BYOK）**；官方积分受 1500/月约束 | 「标准版 AI 写稿不限量（自有 Key）；官方额度 1500 积分/月」 |
| 「年付便宜 29.5%」 | 实际 16.7%（月付 × 10） | 「年付相当于付 10 个月用 12 个月」 |
| 「30 积分约等于 2 条 720P 视频」 | 30 积分 = ¥0.3，买不起最便宜的视频（¥0.6） | 「30 积分可试用 AI 配图/短文本」 |
| 「云端定时发布，关机也能发」 | 只有走云 API 的 `cloud_publish` 才是真关机可发；本地 RPA 定时需要应用托盘常驻 | 「云端 API 发布可关机执行；本地定时需应用常驻」 |

| 「4K / 去水印 / 商用授权」 | 尚未接入档位（当前是全局运营开关或法务条款） | 「规划中，上线后另行公告」 |

## 2. 机制原则（八条硬规则）

> 这八条是「表格不腐化」的约束。任何新增权益、调价、改额度，先过这八条。

1. **单一真源**：所有档位数值只活在 `plan-matrix.js`，经 `GET /api/v1/plans` 与 `/api/v1/me` 下发；客户端禁止硬编码金额/配额。文档只是镜像，冲突以代码为准。
2. **`-1` 白名单**：只有 `maxPlatforms`、`aiWriteMonthly`、`videoMonthly`、`officialCreditMonthly`、`maxDevices`、`maxCloudAccounts`、`batchSizePerRun` 七键可用 `-1` 表示不限；`dailyPublish` 永不允许 `-1`（会击穿 `consumeFeature` 的 `limit >= 0` 校验）。
3. **`features` 是门禁唯一出口**：质变必须落成 feature 名，经 `hasFeatureOf()` 判定，禁止 `plan === 'pro'` 式硬判。新 feature 必须同时登记：矩阵派生、服务端消费点、客户端文案、回归测试，缺一不可。
4. **档位单调**：`free.features ⊂ standard.features ⊂ pro.features`；任何一档不得出现下一档没有的 feature。
5. **数值三关校验**：新键必须进 `NUMERIC_KEYS`（可覆盖）或不可覆盖清单，并过 `validateNumericValue`（整数、≥ -1、白名单 `-1`、`MIN_ONE_KEYS`、`MAX_BY_KEY`）。
6. **承诺与实现三选一**：对外每一行只能是「已强制 / 已交付（软）/ 规划中（有排期）/ 不提供」。禁止「先写表后补码」；「展示但未消费」不得进入对外表。
7. **价值上云**：桌面本地能力（本地 RPA、BYOK 生成、本地渲染）技术上拦不住，也不应拦；能强制的只有「服务端经手的功能」。档位设计必须把付费价值放在云侧（云发布、云同步、云端队列、云端历史），本地功能走荣誉制 + UI 提示。
8. **限用量优于堵功能**：触顶时优先「降速/排队/引导升级/引导 BYOK」，不锁死已付费功能。把付费用户降级成「付费但啥也干不了」= 立刻退款。

## 3. 五层权益栈

> 每一层回答四个问题：卖什么、为什么愿意付、谁强制、成本多少。

### 3.1 L1 平台能力层（额度轴，现状主战场）

- **卖什么**：可管理平台数、日发布量、并发任务、设备数、云同步账号数。
- **为什么愿意付**：账号越多、发布越频繁，手动操作的时间成本呈线性上升；这是最容易算清 ROI 的一层。
- **谁强制**：理想是服务端（发布入口 + 云账号 + 会话）；现状只有云 API 的月额度与批量条数真正强制，平台数是客户端软提示，云账号/设备/并发未接线。
- **成本**：几乎为零（除云发布带宽/队列），属于「定价分层」而非「成本分层」。

### 3.2 L2 工作流自动化层（标准档解锁）

- **卖什么**：定时发布、批量发布、自动流水线（选题→成片→发布）、队列优先级。
- **为什么愿意付**：从「每天手动发」变成「一周排一次」，是时间价值最大的一层；竞品普遍把定时/批量放在第一个付费档。
- **谁强制**：`schedule_batch` / `batch_publish` 已派生但**无消费点**；当前免费用户本地也能建定时（仅登录）。这是「承诺缺口」最大的一层。
- **成本**：调度器与队列的边际成本近零，适合做「低成本高感知」的分档点。

### 3.3 L3 产出质量层（最强付费理由）

- **卖什么**：AI 写作额度、AI 视频额度、官方积分、模型档（基础/标准/高阶）、导出分辨率、去水印。
- **为什么愿意付**：竞品验证的最强单点付费理由是「去水印」与「1080P/4K」；这两项边际成本低、感知极强。
- **谁强制**：`ai_write_monthly` / `video_create_monthly` / `official_credit_monthly` 全部**无消费点**；`tier_access_*` 无模型路由消费点；分辨率/去水印当前是全局运营开关，不是档位。
- **成本**：这是唯一有真实成本的一层（模型算力）。必须与积分费率、`tier_access` 联动，不能「高档全模型随便用」。

### 3.4 L4 商业化层（内容资产归属与用途）

- **卖什么**：商用授权、多版本改写、品牌模板、导出无水印/打包、完整白标。
- **为什么愿意付**：B2C 付费的分界线是「我能不能拿它赚钱」；代运营/工作室对商用授权敏感。
- **谁强制**：法务条款 + 导出链路；当前均未落地（白标只有视频水印文本/位置/透明度，没有 logo/域名/品牌配置）。
- **成本**：法务与模板设计成本，边际成本低。

### 3.5 L5 治理层（最高档专属：管控、审计、优先级）

- **卖什么**：发布历史保留期、数据导出、API 开放平台、优先支持、团队席位/SSO/审计。
- **为什么愿意付**：矩阵越大，越需要「出问题能查、能导、能追责」；这是专业档与团队档的分水岭。
- **谁强制**：历史保留/导出未接；API 未产品化；优先支持只有静态帮助页；团队能力不存在。
- **成本**：存储与人力客服成本，适合放在最高档。

### 3.6 各层与档位的对应

| 层 | 免费版 | 标准版 | 专业版 |
|---|---|---|---|
| L1 平台能力 | 5 平台 / 5 条/日 / 1 并发 / 2 设备 / 0 云账号 | 15 平台 / 50 条/日 / 3 并发 / 3 设备 / 20 云账号 | 不限平台 / 1000 条/日 / 10 并发 / 不限设备 / 不限云账号 |
| L2 自动化 | 单篇即时发布 | + 定时 + 批量 10 条 + 队列 | + 批量不限 + 队列优先级 + 自动流水线（规划） |
| L3 产出质量 | 200 次 AI 写稿 / 0 视频 / 30 积分 / 基础模型 / 720P | 不限写稿（BYOK）/ 300 视频 / 1500 积分 / 标准模型 / 1080P（规划） | 12000 写稿 / 3000 视频 / 3000 积分 / 高阶模型 / 4K（规划） |
| L4 商业化 | 个人非商用 | 商用授权（规划）/ 多版本 3 次（规划） | 商用授权（规划）/ 多版本不限（规划）/ 品牌模板（规划） |
| L5 治理 | 7 天历史（规划）/ 社区支持 | 90 天历史（规划）/ 数据导出（规划）/ 工单（规划） | 不限历史（规划）/ API 配额（规划）/ 专属支持（规划） |

## 6. 额度校准与经济学

### 6.1 两条守线

| 口径 | 守线 | 现状 | 余量 |
|---|---|---|---|
| 月付官方积分成本占比 | ≤ 30% | 标准 25.42%（¥15/¥59）；专业 25.21%（¥30/¥119） | 4.6 / 4.8 个点 |
| 年付官方积分成本占比 | ≤ 40% | 标准 30.51%（¥180/¥590）；专业 30.25%（¥360/¥1190） | 9.5 / 9.8 个点 |

> 积分单价按 ¥0.01/积分计。年付按月等额发放，年付总量恒为 12 × 月付量；**不设年付专用字段**，避免两套数值漂移。

### 6.2 为什么是 1500 / 3000

- **1500**：在两条守线内，且能被 H3 768P 10 秒（500 积分）整除 ⇒ 宣传口径可写「每月 3 条 10 秒 768P」。
- **3000**：同理整除 ⇒ 「每月 6 条 10 秒 768P」；月付占比 25.21%、年付 30.25%，比旧值 3330（正好压在 40% 守线、余量 0）更安全。
- **30（免费）**：¥0.3，只够 1 张标准配图，买不起最便宜视频 ⇒ 免费档禁视频的定量依据。

### 6.3 额度校准方法（新增额度必须走一遍）

1. **定画像**：目标用户每月发布条数、平台数、视频条数、AI 写稿篇数的 p50 / p75。
2. **乘余量**：额度 = p75 × 2–3 倍。低于 2 倍会在旺季触顶，高于 3 倍等于没分层。
3. **过五要素**：度量物（条/次/积分）、阈值、触顶行为（阻断/排队/降速/引导）、付费差异、重置周期。
4. **算成本**：按官方成本价算占比，过 6.1 两条守线。
5. **写宣传口径**：必须能用一个整数除尽（如「每月 3 条 10 秒」），否则客服解释不清。

### 6.4 积分与会员费的分工

| 买什么 | 用什么付 | 规则 |
|---|---|---|
| 平台能力（发布、账号、自动化、看板、设备） | 会员费 | 按档位，不消耗积分 |
| AI 用量（官方模型算力） | 积分 | 会员每月发放额度；用尽后可买积分包或切自有 Key |
| 自有 Key（BYOK） | 用户自付给模型商 | 免积分，但**功能配额照旧受档位约束**，否则成熟用户全部 BYOK + 买最低档 |

> 积分定价的完整推导见 `01-docs/PRD-CREDIT-PRICING-2026-10-25.md`，本文不重复。

### 9.2 六条结构规律

1. **四档是主流**：15 个样本中 9 个为「免费 + 入门 + 专业 + 团队/企业」；国内分发工具多为三档。第四档全部由团队协作/合规/SLA 支撑。
2. **平台数几乎不分档**：行业用「账号/品牌数 × 每月发布量/credits × 席位」计量；平台数不是计价单位。我们目前以 `maxPlatforms` 为主轴，属于少数派，需在下一轮评估是否迁移到「绑定账号数」。
3. **免费档有三种定位**：获客型（卡第二个账号，如 Buffer/Publer）、产量型（账号给够但限每日/每月发布，如参考产品 R1/易媒）、演示型（无永久免费，只给 7–14 天试用，如 Hootsuite）。我们选「获客 + 产量」混合。
4. **低成本高感知的分档点**：去水印、1080P/4K、看板回溯期、定时/批量、AI 额度、白标、优先支持。这些应放标准/专业档做溢价。
5. **硬成本项做计量单位**：账号数、席位、处理分钟、credits。加购包是第二增长曲线，且「加购不过期」本身是付费特权。
6. **队列优先级被明码标价**：可灵/即梦/Luma 都用「排队 vs 快速通道」做档位差；我们的 `concurrent_tasks` 目前只下发不执行，是明显缺口。

### 9.3 五个直接对标与启示

| 对标 | 为什么直接 | 可借鉴 | 我们不能照搬 |
|---|---|---|---|
| 参考产品 R1（桌面分发） | 同为 Windows 桌面、多平台多账号一键分发 | 免费卡「产量」而非账号数；付费按账号包叠加，计量极清晰 | 它是纯分发，没有 AI 视频/写作，不能把它的低价当我们的价格锚 |
| 易媒助手 | 功能面重叠度最高：70+ 平台、AI 写作/混剪、评论聚合、团队子账号 | 个人三档 + 团队三档；批量条数单独卡；7 天试用 | 它的团队版有真实席位体系，我们没有 |

## 12. 风险与未决

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 本地能力拦不住，免费用户可无限本地发布 | 付费转化受损 | 价值上云；本地软配额；把「云发布/云同步/云端历史」做成付费理由 |
| R2 | 免费档薅号（30 积分 + 150 云发布/月） | 成本 <¥1/月/号，但黑产可批量 | 设备软上限 2 + 高成本动作验证 + 注册频控；先保护视频/积分 |
| R3 | 支付未接通 | 无法验证真实转化；试用/proration 无法做 | P2-PAYMENT 前置；先用兑换码/后台开通跑通闭环 |
| R4 | 价格版本迁移 | 老用户价格锁定/升级补差未定义 | 支付接通前建立「价格版本 + 老用户保护」规则 |
| R5 | 团队档语义被销售误用 | 交付翻车 | §1.3 禁用词；合同中明确「单账号多设备」 |
| R6 | 竞品数据时效 | 剪映/即梦频繁调价 | 定稿前复核 App 内购买页；文档标日期与可信度 |
| R7 | 文档再次漂移 | 已发生四轮（#3178→#4051→#4393→#4454） | 建议新增 `scripts/check-plan-matrix-doc.js`，用 `getPlanCatalog()` 断言本文表格；CI changes job 跑 |

### 未决问题（需 CEO 拍板）

1. **是否把主轴从「平台数」迁到「绑定账号数」**：行业普遍按账号计量；我们只有 `maxCloudAccounts`（云同步账号），本地绑定账号无上限。迁移会影响所有档位文案与门禁实现。
2. **免费档是否保留「本地无限发布」**：技术上拦不住，产品上是否要用 UI 软配额（每日 5 条）表达？
3. **标准版 AI 写稿「不限」是否保留**：BYOK 前提在销售话术里极易丢失，是否改成明确额度（如 3000 次/月）？
4. **是否做 7 天 Pro 试用**：转化率最大杠杆，但需要支付/风控；当前归 P3。
5. **专业版是否保留「日发 1000」**：这是产品上限而非可达量，是否改为「不限（公平使用）」？
