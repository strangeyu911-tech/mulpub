**能不能接的前置问题**（如果选了视频模型，C1「三要素直传」这条根本无从谈起）。
放成 §6.5 既保持逻辑连贯，又不动后续章节编号（避免牵动 §7/§8/§9 的既有交叉引用）。

## CHANGELOG 条目

# docs(research)：新增「数字人 vs 视频模型」判定章节——把排除 MiniMax 的个例判据升级为可复用分类方法

用户提问「数字人出视频」与「视频模型（Seedance）拿本人照片生成视频」有何不同，据此在调研报告
新增 §6.5（7 个子节），并把 §6.1 里排除 MiniMax 的**个例理由**一般化成**分类方法**。

### 核心判据

**数字人的嘴是被音频驱动的（音素时间轴 → viseme，确定性）；
视频模型的嘴是被 prompt 生成的（与画面一起在像素空间生成，概率性）。**

这一条决定了：人物一致性、单次时长（数字人=音频长度；视频模型 4–15 秒）、可重复性、
长文案处理方式（一次出完 vs 切段拼接且接缝处人物会变）。

### 对口播场景的判决

3 分钟文案用视频模型要拼 12–36 段，人物漂移且口型不对应 ⇒ **语义上不满足需求，
不是「更便宜的替代」**。这解释了为什么 MiniMax（音色克隆 + 视频生成 + 完整 API 全都有）
仍然必须排除。

### 可操作性

给出**五个当场可问的判断问题**（输入有音频轨吗 / 口型按音素时间轴还是模型猜 / 单次最长多少秒 /
同形象同文案两次一致吗 / 换文案人物会变吗），第 1、4、5 题答「否/会变」即生成式路线。

### 两个容易被低估的维度

- **成本**：数字人按分钟显性可预算；视频模型是「表价 × 重试次数 × 片段数」，隐性乘出来。
  15 秒片段重试 5 次即单价 ×5，3 分钟拼 20 段则是乘出来的成本。
- **责任**：形象库的商用授权 vs 参考图的肖像权风险在集成方——商用场景下这条比技术指标更致命。

### 一个自证式证据

可灵把「对口型」做成**独立功能**，本身就说明其视频生成不自带准确口型，必须再叠一道 lipsync。
所以判断路线要按机制，不能按产品名。
