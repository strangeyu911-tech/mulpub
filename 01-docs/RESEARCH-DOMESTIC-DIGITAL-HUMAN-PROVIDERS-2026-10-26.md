# 国内数字人服务商调研报告（2026-10-26）

> 载体性质：**技术调研报告**（非 PRD、非执行记录）。
> 服务对象：`avatar-spokesperson`（外显「数字人口播」）流水线的 provider 多源化选型。
> 关联文档：`01-docs/PRD-AVATAR-SPOKESPERSON-HEYGEN-WIRING-2026-10-19.md`（决策 D3 预留了
> `params.videoProvider` 覆盖口子，本报告即该口子的候选清单与实证依据）。

---

## 1. 背景：为什么要做这份调研

2026-10-19 合入的 #3969 把 `avatar-spokesperson` 流水线从「名义登记、实际走通用文生视频」
修成真正接通数字人，但当时只接了一个 provider：`DIGITAL_HUMAN_PROVIDER = 'heygen'`（海外）。

由此留下三个结构性缺口：

| 缺口 | 具体表现 |
|---|---|
| **单点依赖** | 该 provider 的 Key 失效/额度耗尽/网络不可达时，整条流水线不可用，无降级路径 |
| **跨境成本** | 外币结算、跨境网络、实名与合规白名单，对国内用户是持续摩擦 |
| **语言/口型适配** | 中文口播的韵律、多音字、方言腔调，国内厂商普遍更优 |

本报告的目的不是「换掉它」，而是**把候选面铺开并给出可验证的接入判据**——换不换是后续
独立决策，本次只交付事实与适配性分析。

## 2. 数据可信度分级（本报告的取证纪律）

本报告所有价格与能力结论均标注等级。**未标注等级的数字不得写入 PRD 作为验收依据。**

| 等级 | 含义 | 可否直接用于选型决策 |
|---|---|---|
| **A** | 本次从官网公开页/官方文档**直接抓取原文** | 可以（仍需注意页面更新时点） |
| **B** | 官方存在定价/文档页面，但内容在登录墙后或 JS 渲染未取到具体数字 | 需补一次登录态取证 |
| **C** | 第三方媒体/博客/工具站转述 | 不可直接采用，须商务核实 |
| **X** | 域名在本机 DNS 被策略拦截，本次**完全未实测** | 不可采用 |

### 2.1 本次调研的取证边界（必须一起读）

1. **通用搜索后端不可用**：`web_search` 走 DeepSeek 端点，本次全程返回
   `HTTP 402 Insufficient Balance`。候选厂商来自既有导航站清单 + 已知厂商定向验证
   + 语义检索补搜——**覆盖面仍是「已知集合」而非「全网穷举」**。
2. **大量厂商域名在本机被 DNS 解析拦截**（返回「resolves to a non-public IP」或
   `ENOTFOUND`），包括但不限于：蝉镜主站与文档站、闪剪主站、秒创、有言、KreadoAI、
   万兴播爆子域、即构、云舶、世优等。这些一律记为 X 级，**不臆测其价格**。
3. **价格全部为「页面公示价」**，不含商务折扣、活动价、阶梯返点。国内 To-B 数字人
   几乎都存在「挂牌价 → 实际成交价」的落差，决策前必须走商务询价。
4. 页面价格随时调整，本报告所有数字带**抓取日期（2026-10-26）**，超过 1 个月应重新取证。
5. **云厂商的官方按量价是本报告中最硬的一档数据**（阿里云、华为云都在帮助中心公示到
   「元/分钟」且带生效日期），优先级高于任何订阅制产品的折算值——见 §5.4 的交叉校验。

## 3. 市场格局：四类形态（这是选型的第一道筛子）

数字人服务在接入形态上分成四类，**与「好不好用」无关，与「能不能程序化调用」强相关**：

| 形态 | 特征 | 代表 | 可否接入本流水线 |
|---|---|---|---|
| **① API-first** | 提交任务 → 轮询状态 → 取片，有开放平台文档与密钥体系 | **腾讯云数智人**、**阿里云 DVH**、**华为云 MetaStudio**、**飞影数字人**、**京东言犀**、蝉镜开放平台、闪剪开放平台、讯飞虚拟人、百度曦灵、火山引擎、硅基智能、相芯科技 | ✅ 可适配现有 adapter 契约 |
| **② SaaS 工具** | 网页/客户端内人工操作，无公开 API 或 API 仅企业版 | 商汤 Seko、即梦、开拍、万兴播爆、奇妙元、有言、来画 | ⚠️ 只能给人用，程序化接入需另谈企业接口 |
| **③ 直播专用** | 7×24 数字人直播带货，能力重心在运营而非成片 | 百度慧播星、硅基 AI 直播、即构数智人 | ⛔ 与本仓库「口播成片」场景不同轴 |
| **④ 开源自部署** | 本地跑模型，无边际调用费 | 硅基智能 Duix.Heygem / Duix.Avatar | ✅ 但需评估算力与运维成本 |

**第一道筛子的结论**：形态②③④之外的候选约 **12 家**，而非坊间常说的「几十家数字人公司」。

### 4.4 一处已纠正的漏检：腾讯不是「退出」，是「换了产品线」

**初版结论（错误）**：腾讯智影产品页返回 404 ⇒ 记「已退出评估」。

**纠正（本版）**：SPA 产品页 404 只说明那条**前端入口**不在了，不等于腾讯退出数字人市场。
腾讯有一条**独立的、在售的**产品线——**腾讯云智能数智人（TCADH，文档 `product/1240`）**，
其《价格指南》最近更新于 **2026-07-17**，售卖结构完整（形象采购 + 播报服务 + 交互服务），
并配有视频生成服务 API 与云渲染/端渲染 SDK。已单列进 §4.1。

| 认知 | 事实 |
|---|---|
| 腾讯智影（zenvideo / 消费端 SPA） | 产品页 404，前端入口已下线 |
| **腾讯云智能数智人（TCADH）** | **在售**，价格指南 2026-07-17 更新，企业向，组合购买 |

> **这条要写进方法论**：判断一家厂商「是否还在做」，不能只看一个消费端产品页的 HTTP 状态码。
> 大厂常有「消费端 SPA 下线、企业端云产品在售」的分裂形态。正确做法是查**云厂商的产品文档
> 目录**（`document/product/<id>`）与**价格指南的 `最近更新时间`**——后者是「是否在售」的
> 最可靠信号（长期不更新的价格页通常意味着产品停滞）。
>
> 同类风险在本报告里还有一处：火山引擎的数字人产品线本次因文档站 JS 渲染未取到内容，
> 判为「A（存在）/ B（价格）」而非「不存在」——同一个道理。

#### 5.3.1 ⚠️ 同一家厂商的价格在不同报道里差 60 倍——这是口径冲突，不是数据错误

查证过程中遇到一对必须并列记录的数字，**任何引用都必须带上口径**：

| 数字 | 出处与时点 | 口径推断 |
|---|---|---|
| 百度曦灵 3D 超写实数字人 **¥199** | 2024-09 云智大会发布（媒体快讯） | 疑为「3D 超写实**形象**的起售价/单次价」，非定制整套 |
| 百度曦灵 3D 数字人降到 **¥1.2 万** | 2024-08 行业访谈（同行 CEO 转述） | 疑为「**定制**一个 3D 数字人」的整套价格 |

两者相差 60 倍，但**很可能都是真的**——它们是不同商品。同类历史锚点可佐证这个量级带：
2022 年媒体报道「定制一个**卡通风格**数字人 3–5 万元，再加面部及全身动作捕捉 + 直播系统
共 9–20 万元」。

⇒ **本节的方法论要求**：引用厂商价格时**必须写清"是什么商品"**——
是形象本身、是定制交付、是按分钟推理、还是套餐内额度。本报告之所以对每家都写
「价格锚点」而非单一数字，原因就在这里。

> 顺带一条行业侧写：世优科技 CEO 在 2024-08 访谈中说「AI 数字人价格战打得很厉害，
> 六七成竞争对手都倒下了」。这与本报告观察到的「2D 定制价格带三年未变、3D/软件侧
> 疯狂降价」是同一现象的两面——**降价发生在软件与模型侧，人工交付侧没有降**。

### 5.4 交叉校验：为什么不能引用「¥2/分钟」当市场价

本节是本报告最重要的方法论结论，**必须在任何引用本报告的地方一起读**：

同一个「1 分钟数字人口播视频」，不同口径差 **12 倍**（最低 ¥0.83，最高 ¥10）：

| 口径 | 数值 | 来源 |
|---|---|---|
| 订阅制折算（飞影个人版） | ≈ **¥0.83/分钟** | §5.2，¥99/月 ÷ 120 分钟额度 |
| 订阅制折算（蝉镜） | ≈ **¥2.0/分钟** | §5.2，分母是「官方声明的额度上限」 |
| 官方套餐包（华为云 6,000 分钟） | **¥4/分钟** | §5.1（量越大越便宜） |
| 官方套餐包（华为云 60 分钟） | **¥8/分钟** | §5.1 |
| 官方按量计费（阿里云） | **¥9.9/分钟** | §5.1 |
| 官方按量计费（华为云） | **¥10/分钟** | §5.1 |

**差异的来源（逐条可查，不是「厂商乱定价」）**：

1. **蝉镜的分母是「最多」而非「平均」**——95 分钟是 5,700 蝉豆在当前档位下能跑出的
   **上限**，实际可用时长受分辨率、文案长度、模型档位影响，向下浮动；
2. **订阅制捆绑了非视频权益**——形象克隆、声音克隆、模板、去水印、团队协作都在套餐里，
   把包月费全摊到分钟数上，等于把「软件订阅费」算成「视频生产成本」；
3. **云厂商的按量价是「纯推理」计价**——形象要另外买（5,999–6,999 元/个），
   而订阅制常把形象克隆打包赠送；
4. **量级折扣差异巨大**——华为云 6,000 分钟包折算 4 元/分钟，是 60 分钟包（8 元）的一半；
   任何「平均价」都必须声明对应的用量档位；
5. **飞影的 ¥0.83 是「工具订阅」而非「云服务」**——¥99/月给的是「2 小时额度 + 1 个席位」，
   本质是给个人创作者的工具包，不含企业级 SLA、并发保障、私有化、合规审计；
   云厂商按量价卖的是「可嵌入业务的推理服务」。**两者不可直接比价**，只能各自参照。

⇒ **正确用法**：做成本测算时用「官方按量价 × 预计分钟数 + 形象一次性费用」，
而不是拿订阅制折算值当单价。**本报告不给出「市场均价」结论。**

⇒ **选型时的正确读法**：这 12 倍跨度不是"同一件商品的市场波动"，而是**两类商品**
（创作者工具包 vs 企业推理服务）各自内部的合理区间。先决定你要买哪一类，
再在那一类里比价——跨类比价只会得出"最便宜的也是最好的"这个错误结论。

## 6. 接入适配性矩阵（本报告最实用的一节）

现有契约（`apps/desktop/electron/services/adapters/_base/base.js` + `digital-human-stages.js`）：

```
callAdapter(providerId, 'generateVideo', { character, voice, script })
  → 返回 { videoId }
callAdapter(providerId, 'getVideoStatus', { videoId })   // 轮询
  → 返回 { status, videoUrl }
→ 下载到 scene_000.mp4
```

四个**硬约束**决定「能不能接」：

| 约束 | 判据 | 说明 |
|---|---|---|
| C1 三要素直传 | 接口能否一次接收「形象 ID + 音色 ID + 文案」 | 若需先各自建任务再拼接，需在 adapter 内做状态机 |
| C2 异步任务模型 | 是否有「提交 → 查询」两段式 | 同步阻塞式接口在长文案下必然超时 |
| C3 结果可下载 | 返回的是**可下载 URL** 还是仅控制台内预览 | 只给预览链接的（多数 SaaS）直接排除 |
| C4 密钥体量 | 单 Key + 单 baseURL 即可调用 | 需 OAuth 多步换 token 的，要在 adapter 内加 token 缓存 |

### 6.1 为什么 MiniMax 必须单独说明「排除」

它是最容易被误纳入的一家：既有 10 秒音色克隆、又有视频生成、还有公开 API 与完整定价，
**表面看什么都有**。但它的视频模型是**生成式视频**（文生/图生/首尾帧/全能参考），
产物里的人不会按你给的文案逐字对口型——那是「数字人」与「AI 视频」两类能力的本质分野。
把它接进 `avatar-spokesperson` 会得到一个「画面在动但嘴不对」的成片，属于**语义错配**，
比不接更糟。

### 6.2 云厂商特有的一条坑：形象是「固定资产」而非「即时资源」

阿里云 2D 定制需上传 5–10 分钟视频、**算法训练最长 10 个工作日**、人工审核通过后才开始训练，
且**不支持退款**；华为云的形象制作同样是一次性预付费时长包（5,999 元/个）。这与 heygen 那种
「选一个现成 avatarId 立刻就能用」的形态**根本不同**。

⇒ 对 UI 的影响：`avatar_select` 阶段必须区分**「现成形象」（即时可用）**与
**「定制形象」（有等待期、有审核、有不可退费用）**两类资产，
不能共用一个下拉列表——否则用户会以为「选完就能出片」，实际要等两周。

### 6.3 腾讯的「免训练版」是目前与现有契约最贴合的形态

腾讯云数智人把「形象」与「合成」拆成了可独立购买的商品，其中一条路径值得单独强调：

| 模式 | 需要先买形象？ | 素材要求 | 交付速度 |
|---|---|---|---|
| 训练版 | ✅ 要（租赁 50 元/月起，或定制 2,500 元起） | 60s / 180s / 4K 视频，1–3 天出 demo | 慢 |
| 照片数智人 | ✅ 要（定制价极低） | **一张照片** | **10 分钟** |
| **免训练版** | ❌ **不需要** | **一段真人视频素材** + 文本或音频 | 即时（按小时包计费） |

**为什么这条最贴合**：现有 `avatar-spokesperson` 的契约是
「给 `character` + `voice` + `script` → 出一条口播视频」。免训练版正是
「给一段人物视频 + 文案 → 出口型匹配的新视频」，**不需要预先在厂商侧建立形象资产**，
也就不需要 `avatar_select` 之外再引入「形象采购/训练/审核」这一整套前置流程。

⇒ 代价：免训练版按小时包计费（国际站 10 小时 4,500 美元量级），单价比训练版贵；
且产物资源**只保留 7 天**，adapter 必须立即下载，不能像 heygen 那样留 URL 慢慢取。

### 6.4 飞影的定位：门槛最低，但是「工具包」不是「云服务」

飞影有完整的 API V2 开放平台（`api.hifly.cc`，Bearer Token 认证，个人中心直接取 token），
接入复杂度是所有候选里最低的。但要注意它的商品结构：

- 个人版 ¥99/月、专业版 ¥399/月 是**面向创作者的 SaaS 订阅**，不等于 API 可用
- **API 接入挂企业版**（官网 FAQ 明确「企业版含私有化部署、API 接入、专属客服」）

⇒ 所以「¥99/月就能用 API」是误读。真要接 API 走企业版报价——这条必须在选型时问清，
否则会按 ¥99 做预算、到商务环节发现不是这个数。

## 7. 选型建议（分阶段，不一次做完）

### 7.1 推荐路线

| 阶段 | 动作 | 理由 |
|---|---|---|
| **P0（本次不做，仅登记）** | 保持 `heygen` 为默认；把 `params.videoProvider` 的**校验白名单**从「只认 heygen」放宽为「已注册的数字人 provider 集合」 | 不改任何运行时行为，只把扩展点从「隐式」变成「显式」，风险最低 |
| **P1** | 接**一家**做 PoC | 单 provider PoC 可验证「adapter 契约是否真的通用」，避免一次性铺 3 家的返工 |
| **P2** | 若 PoC 通过，再接第二家 | 两家才构成「降级路径」，一家不构成 |
| **P3** | 独立评估 Duix.Heygem 本地部署路线 | 唯一能把「按分钟成本」变成「一次性成本」的选项，但改动面完全不同（要打包模型/依赖 GPU），不应与 adapter 工作混在一起 |

**P1 候选的取舍（五家各有明确取舍，没有「最优」）**：

| 候选 | 选它的理由 | 选它的代价 |
|---|---|---|
| **腾讯云数智人（免训练版）** | **形态最贴合**：不需预先建形象资产，一段视频 + 文案即出片；API/进度查询齐全；形象租赁最便宜（50 元/个/月） | 按小时包计费（单价高）；产物**只留 7 天**，必须立即下载 |
| **阿里云 DVH** | 定价最透明（9.9 元/分钟精确到秒）；2D/3D 双形态；帮助中心 API 文档完整可读；境内备案齐全 | 单价最高档；2D 定制 6,999 元/年 + 10 工作日等待 |
| **华为云 MetaStudio** | 分钟价最低档（6,000 分钟包折算 4 元/分）；调价公告把原价/现价并列，可核性最好 | 形象制作 5,999 元/个是硬门槛；声音进阶版另计 6,999 元 |

| **飞影数字人** | 接入门槛最低（Bearer Token，个人中心取）；克隆素材要求最低（5 秒视频） | API 挂**企业版**（¥99/月的个人版不含 API）；企业级 SLA/合规待核实 |

### 7.2 明确不建议做的事

| 不做 | 原因 |
|---|---|
| 一次性接 3–5 家做「provider 矩阵」 | 每家的参数归一化、错误码映射、额度预检都要单独写；在没验证「契约通用性」前铺量，返工率极高 |
| 把 SaaS 形态厂商（Seko/即梦/万兴播爆）硬包成 adapter | 无 API 就只能自动化浏览器，属另一类工程（且违反厂商 ToS 风险） |
| 用 MiniMax 的 TTS + 视频拼「伪数字人」 | 口型不同步，见 §6.1 |
| 在订阅制折算值上写「市场均价 ¥2/分钟」 | 与官方按量价差 3–5 倍，见 §5.4 |
| 把「现成形象」与「定制形象」混在一个下拉里 | 后者有 10 工作日等待 + 审核 + 不可退费用，见 §6.2 |

## 8. 若进入 P1，需要提前定的规格（供后续 PRD 直接引用）

本节把调研结论转成**可执行的接入规格骨架**，避免下一轮 PRD 从零开始。

### 8.1 数据校验规则（启动前拦截，不白跑 LLM）

| 校验项 | 失败错误码 | 用户可见提示（locale 键） | 拦截时机 |
|---|---|---|---|
| 未选形象 | `AVATAR_ID_REQUIRED` | `avatarErrSelectAvatar` | 启动按钮禁用 + 原因常驻 |
| 未选音色 | `AVATAR_VOICE_REQUIRED` | `avatarErrSelectVoice` | 同上 |
| provider 未配置 Key | `AVATAR_PROVIDER_NOT_CONFIGURED` | `avatarErrProviderMissing` | 整区替换为「前往配置」引导 |
| provider 不支持该能力 | `AVATAR_CATALOG_UNSUPPORTED_PROVIDER` | `avatarErrUnsupportedProvider` | 目录加载时 |
| **额度不足**（国内厂商特有） | `AVATAR_QUOTA_INSUFFICIENT` | `avatarErrQuotaInsufficient` | **启动前**，不得跑到生成阶段才失败 |
| **形象仍在训练/审核中**（云厂商特有） | `AVATAR_NOT_READY` | `avatarErrAvatarNotReady` | 选中该形象时即提示剩余等待 |
| 形象已被厂商下架 | `AVATAR_NOT_AVAILABLE` | `avatarErrAvatarUnavailable` | 目录刷新时从列表剔除 |
| **按分钟计费预计超预算** | `AVATAR_COST_EXCEEDS_LIMIT` | `avatarErrCostExceedsLimit` | 启动前按文案字数估算时长后校验 |

> 后三条是国内/云厂商新增的失败形态，heygen 时代不存在。**必须新增**，
> 否则用户会看到「排队很久然后失败」或「出片才发现扣了一大笔钱」。

### 8.2 状态机（比现役 heygen 多三态）

```
idle → validating → submitting → polling → downloading → done
                       ↓           ↓          ↓
                   rejected     timeout    downloadFailed
                       ↓
                  quotaBlocked（新增：额度不足，不可重试，需充值）
                  costBlocked （新增：预计超预算，不可重试，需调整）
                  notReady    （新增：形象未就绪，不可重试，需等待）
```

| 状态 | 可重试 | 提示文案键 |
|---|---|---|
| `quotaBlocked` | ❌（重试必然再失败） | `avatarStateQuotaBlocked` |
| `costBlocked` | ❌ | `avatarStateCostBlocked` |
| `notReady` | ❌ | `avatarStateNotReady` |
| `rejected`（内容审核驳回） | ❌ | `avatarStateRejected` |
| `timeout` | ✅ | `avatarStateTimeout` |

> **内容审核驳回**同样是被低估的一类：国内厂商普遍有审核前置，文案命中敏感词会在提交阶段
> 就被拒，而 heygen 侧不存在这条路径。若不加区分地归入「生成失败」，用户会反复重试。

### 8.3 显示项（配置区）

| 显示项 | 数据来源 | 空态 |
|---|---|---|
| 形象下拉 | `avatarCatalog.avatars(providerId)` | 「该服务商暂无可用形象，点击刷新」 |
| 音色下拉 | `avatarCatalog.voices(providerId)` | 同上 |
| 刷新按钮 | 触发 `invalidate` + 重新拉取 | 加载中禁用 + spinner |
| **额度余额**（新增） | 各 provider 的配额查询接口（若无则隐藏） | 不显示该行 |
| **形象就绪状态**（新增） | 按 `avatar.status` 分「可用 / 训练中（剩余 N 天）」 | 训练中项**置灰不可选** |
| **预计费用**（新增，按量计费 provider） | 文案字数 → 预估时长 × 单价 | 字数未知时显示区间 |
| provider 标识 | 当前解析到的 `videoProvider` | 显示为只读文本，避免用户误以为可在此切换 |

### 8.4 交互逻辑要点

1. **切换 provider 时清空已选的 `avatarId`/`voiceId`**——不同厂商的形象 ID 空间不通用，
   保留旧值会导致提交时才报「形象不存在」；
2. 目录缓存 TTL 沿用现役的 5 分钟，但**额度余额不进缓存**（余额是高频变化量，缓存会误导）；
3. 刷新失败时若曾成功过，**保留旧列表并提示**（现役四态已实现，不回归）；
4. 按量计费 provider 的「预计费用」应在**文案变更时实时重算**（防抖 500ms），
   而非只在启动时算一次。

## 附二：本报告的三轮自我纠错（方法论留痕）

这份报告经过三轮补正，三次都是**用户指出或补搜才发现**的，不是初版自己覆盖到的。
留痕以免后续误信「已完备」：

| 轮次 | 漏了什么 | 为什么会漏 | 修正后的判据 |
|---|---|---|---|
| 第 2 轮 | 阿里云 DVH、华为云 MetaStudio | 只顺着「数字人 SaaS 厂商」这条线找，没把**云厂商的数字人产品线**当独立类目 | 云厂商必须逐个查 `document/product/<id>` 目录，不能只搜「数字人平台」 |
| 第 3 轮 | **腾讯云智能数智人**、飞影数字人 | 腾讯：只看消费端 SPA 页返回 404 就判「已退出」，没查企业端云产品文档；飞影：它不在主流导航站的"数字人"分类前列 | ① 「产品页 404」≠「厂商退出」，须查云产品文档与价格页更新日期；② 导航站分类不是全集，须交叉多源检索 |
| 第 4 轮 | **商汤如影**（独立于 Seko 的另一条线）、京东言犀、小冰 | 商汤：只记了消费端 Seko，没查其企业数字人产品线（`senseavatar`）；京东/小冰：都在导航站"数字人"分类之外 | ③ **同一家公司可能有多条互不相同的数字人产品线**（商汤：Seko / 如影；腾讯：智影 / 云数智人；百度：曦灵 / 慧播星 / PDH），必须按公司逐条枚举，不能一家记一条 |

三次漏检的共同根因：**用单一分类维度（"数字人 SaaS"）去枚举一个跨界市场**。
数字人同时属于「SaaS 工具」「云 AI 服务」「开源自部署」「直播系统」四个货架，
且**大厂内部还有多条并行产品线**，只逛一个货架、一家只记一条，必然漏。

⇒ 同类调研的启动检查项（三条）：
1. 按**货架**枚举（SaaS / 云 AI / 开源 / 直播），不只按"品类"搜；
2. 按**公司**枚举，一家查完所有数字人产品线（用 `site:` 或厂商文档目录）；
3. 「产品页 404」只判该入口下线，**不判厂商退出**——查价格页的「最近更新时间」。
