# Spec: createview-config-profile-extract

## Requirement 1：拆分决策必须以「仓内定案 + 当前数据复评」为准，不得凭单一来源拍板

- 任何 CreateView.vue 拆分决策，必须同时给出：① 仓内定案文档 `01-docs/FRONTEND-FILE-SPLIT-PLAN-2026-10.md`
  的既有结论；② 当前基线上的**实测复评数据**。
- **既有的「不做」结论是时点结论**，其依据（触点、冲突频率）随代码演进失效时，
  必须**复评并显式记录依据的变化**，不得以「文档写了不做」为由直接继承，也不得以「底稿说该拆」为由直接开工。
- 复评必须给出**诚实边界**：若所用口径与定案文档不同源，则只做同次测量内的相对排序，
  **不得与定案数字直接对比**；同源的口径（如冲突频率）才是主证据。
- 复评结论必须区分「论证错误」与「前提失效」：前者要改论证，后者要改结论并写明前提。

#### Scenario: 有人只读了仓外分析底稿就开工

- **WHEN** 某条拆分决策的依据只有一份仓外底稿，未检索 `01-docs/` 下的定案文档
- **THEN** 判不通过 —— 决策依据必须同时包含仓内定案结论与当前基线实测复评数据

#### Scenario: 复评发现原结论的依据已变

- **WHEN** 实测显示原「不做」依据的判据值显著改善（如冲突频率由 7/50 降至 1/50）
- **THEN** 复评必须把该域改判为「重新成为候选」，并在文档中写明**依据 ① 与依据 ② 各自是否仍成立**，
  以及**哪些域维持原结论**

## Requirement 2：规格必须覆盖实现期会踩的硬约束，不得只写范围

- 第一刀规格（不论最终是否执行）必须逐条写明：① 范围与不搬走项；② 状态处置（是否抽 `data` 状态，
  附 `data.size` 现状与余量）；③ 桥接的兼容契约（整体赋值 / 原地变异返回同引用）；
  ④ 既有数据校验逐条的行为；⑤ 用户视角流程与各分支；⑥ 显示项与交互是否变更；⑦ 提示文字落点与 i18n 约束；
  ⑧ 风险清单；⑨ 验收判据。
- 涉及浮层弹窗组件化时，必须显式声明是否触发仓内的**浮层互斥合同**（owner 登记 + 释放兜底 + 断言同步）；
  触发则该步不得与其它改动混批。
- 规格必须写明**实施期的门禁连带影响**（如：按行号存储的基线在行号偏移后失配 ⇒ 须重生成且须证明无新增命中）。

#### Scenario: 规格只写了「抽哪个域」

- **WHEN** 一份拆分规格只有范围与行数，没有状态处置、数据校验、流程、提示文字、风险与验收判据
- **THEN** 判不通过 —— 缺任一项即视为「未到可实施状态」

## Requirement 3：拆分与验证必须同批，不得把未验证的重构先合入

- 仓内既定的视觉回归验证（QM-4 像素回归）若**不在当前执行环境内可运行**，
  则**实现不得单独合批** —— 规格与实现分批，实现与像素回归同批。
- 分批时，**不得把未做的事写进 tasks 并勾选**：active change 的 tasks 只能列**已实际完成并可取证**的事项。
- 后续工作以「后续 change 预告」形式写在 design 中，**不进本 change 的 tasks**。

#### Scenario: 实现已写好但像素回归跑不了

- **WHEN** 某批实现无法在当前环境完成视觉回归验证
- **THEN** 该批实现**不得单独提交/合并**；须与可完成验证的环境同批进行，或明确标注为未验证并推迟合并

## Requirement 4：新增 composable 的形态约束

- 新增 composable 的**状态归属**必须显式声明：留在壳的 `data()`（则 `data.size` 不变），
  还是移入 composable（则须核算对 `data.size` 下限的余量消耗）。
- 若沿用仓内既有 composable 的模块级单例形态，须先说明该形态的结构性代价
  （把「组件卸载」与「状态生命周期」解耦），并说明本刀为何不受其害。
- **不得照抄遗留形态**：模块级全局兜底（如 `window.__*`）不得引入新文件。
- 代理宿主命名**禁用 `_` / `$` 前缀**；每个代理方法须登记「→ 计划删除 PR 编号」映射。

#### Scenario: 新 composable 引入了 `window.__*` 全局兜底

- **WHEN** 新增 composable 用模块级全局变量兜底注入依赖
- **THEN** 判不通过 —— 全局兜底是既有批次的遗留形态，新代码不得引入
