# 使用手册：复合型全自动化工作流（2026-10-26）

> 适用版本：v1.0（MVP）｜对应 PRD：`PRD-AUTO-WORKFLOW-COMPOSER-2026-10-26.md`

## 1. 这套功能能做什么

一条工作流 = **来源 → 改写 → 生成 → 排期 → 发布**。配好后，应用会在你设定的时间自动采集新内容，去重、改写、做视频/播客，按同账号 35–40 分钟（可改）随机间隔排期，到点发到你选的已添加账号。

典型场景：知乎某个收藏夹里的新文章 → 故事讲述视频 → B站/抖音/视频号/YouTube。

## 2. 第一次使用（5 分钟）

1. 打开左侧「自动化」页 → 点「新建任务」。
2. 任务名称随便起，例如「收藏夹故事视频」。
3. 任务类型保持「复合工作流」。
4. 在「从模板开始」里选「知乎收藏夹 → 故事讲述视频」→ 点「应用模板」。
5. 填三处必填：
   - **收藏夹标识**：收藏夹链接里的 token（多个用逗号分隔）。
   - **视频流水线**：模板已选 `story2video-compose`，不用改。
   - **发布账号**：勾选要发的已添加账号；同一平台可多选，不是选平台。
6. 选一个触发器，例如「每天 09:00」。
7. 点「预览排期」确认节奏，再点「保存」。

> 前提：先在「设置 → 知乎 API」填好 Access Secret；视频生成需要配置可用的模型服务商。

## 3. 六个配置段怎么填

### 3.1 来源

| 来源 | 需要填 | 说明 |
|------|--------|------|
| 热门选题 | 类别（多选）、数量、排序 | 类别至少一个；「按最新」按抓取时间倒序，「按热度」按评分 |
| 关注博主 | 博主 ID（逗号分隔）、每位最多 | 只取「待采集」的新作品；需先在采集页关注该博主 |
| 知乎收藏夹 | 收藏夹 token、数量 | 只给摘要，正文在运行时抓取 |

### 3.2 改写

- **默认策略**：引擎按内容自动匹配；没有有效信号时回退「保真改写」，不会瞎编。
- **指定策略**：固定栏目风格时使用，例如故事化爆款、抖音口播。

### 3.3 内容类型

- **图文**：跳过生成，改写完直接排期。
- **视频**：只能选「文案可直接启动」的 7 条流水线（故事讲述、解释视频、纪录片混剪、动画、数字人、角色动画、混合）。口播/电影感/剪辑工厂需要先导入素材，所以不在列表里。
- **播客**：填播客频道 ID；会生成一期节目并写入 RSS，小宇宙/Apple/Spotify 自动抓取。播客不需要选平台，也不能定时起发。

### 3.4 发布账号与时机

- 在「发布账号」里勾选账号；列表来自「账号管理」里已添加的自媒体账号，按平台分组。
- **同一平台可多选**：例如知乎主号 + 知乎小号可以同时选，两个账号各自独立排队、各自按 35–40 分钟节奏发布。
- 不再按平台默认账号：任务必须至少选一个具体账号，保存时会拦截「只选平台」的配置。
- **立即排队**：生成完就从当前时间开始按间隔排。
- **从指定时间开始**：选一个未来时间（最多提前 30 天）。
- 重要：工作流使用**本地发布队列**，应用必须保持运行（可最小化到托盘）。关掉应用会错过排期；重启后 24 小时内的过期项会自动补发并标「迟到」，超过 24 小时标「错过」不补发。
- 登录已过期/未启用的账号会显示状态且不可勾选；如果任务里的账号后来失效，保存时会被拦截并提示重新登录。
- 队列有派发失败或错过条目时，自动化页顶部会出现黄条；打开「运行记录」可在「发布队列」面板看到失败原因并点「重试」。派发不确定（应用在派发瞬间崩溃）不会自动重发，需要人工确认后重试。
- 生成过程中应用崩溃/重启后，未完成的条目会从上次进度继续；正在排期的条目不自动重发，会标「排期不确定」等人工确认。
- 「抖音爆款库」来源读取的是爆款库里 `platform=douyin` 的已采集内容：先在爆款库录入/采集并填行业，再在工作流里选行业、最低点赞与条数；不会实时抓抖音。

### 3.5 节奏与护栏

- **同账号间隔**：默认 35–40 分钟；每个「平台+账号」独立排队，不同平台可同时发。
- **单次上限**：一次最多处理几条（默认 5，最多 50）。
- **每日上限**：当天最多排几条（默认 20，最多 200）；用尽后整轮失败并提示。
- **发布前需人工审核**：打开后生成完停在「待审核」，在运行记录里点「确认发布」才排期。
- **与已发内容去重**：默认开；按「来源键 + 内容指纹」双键判断，180 天账本。

## 4. 运行记录怎么看

点页面右上角「运行记录」：

- 每条运行显示状态、开始时间、采集/已排期/跳过/失败数量。
- 点开可看每条内容的状态：待处理、采集正文、改写中、生成中、排期中、已排期、已发布、已跳过、失败、待审核。
- 失败条目右侧显示错误原文；来源失败的黄色提示条会说明是哪个来源、什么原因。
- 待审核的运行有「确认发布」按钮；运行中的有「取消运行」。

## 5. 模板

- 内置 5 个模板为只读；应用后可另存为「我的模板」。
- 模板只保存平台建议，不保存账号 ID/凭证；换人使用要重新选择具体账号。
- 导出/导入 JSON 用于团队分发；导出包带 `format/version`，旧版 v1 模板会自动迁移。
- 导入时会重新校验配置，非法配置会被拒绝并指出字段；重名默认加「（导入 N）」，不会覆盖原模板。
- 导入成功后只出现模板下拉里，不会自动应用；需要再点「应用模板」并选账号。
- 账号多时用「搜索账号名称 / 平台 / 备注」过滤；「全选当前结果」只选可见且可用账号，「清空已选」清空全部；「最近使用」可直接点选最近 5 个可用账号。
- 「按平台适配标题/正文/标签」只对已选账号的平台生效：可设标题最多字数、正文最多字数、标题后缀、追加标签；0 表示不限。只改文本，不改封面/视频比例。
- 需要避免半夜/周末发布时，在「节奏」区启用排期规则：选时区、工作日和静默时段；静默内自动顺延，跨午夜也生效。规则只影响新排期，已入队条目不回改。
- 需要控制成本时启用「预算护栏」：填总预算、币种、每项预估；超过剩余预算的运行会直接失败。这里的占用是估算，不是供应商账单。
- 博主监控里被工作流成功使用的条目会显示「已由工作流发布」，不会再次出现在待采集列表；失败条目会回到失败状态以便重试。
- 播客工作流不需要先打开播客页；只要频道和托管已配置，运行时会自动取得出期宿主。

## 6. 常见问题

**Q：为什么任务显示「部分失败」？**
A：至少一条内容失败了（例如某平台账号掉线、视频生成超时），其余条目已成功排期。打开运行记录看失败条目的错误。

**Q：为什么这次只跑了 5 条，我明明有 20 条新内容？**
A：触发了「单次上限」。运行摘要里 `truncated` 会显示原因；把上限调大或分多次运行。

**Q：为什么发布没有准点？**
A：应用当时没开，或者刚重启在补发。看队列条目的 `late` 标记。

**Q：为什么视频一直生成中？**
A：视频流水线单条最长 30 分钟；超时会记失败。先检查模型服务商额度与网络。

**Q：为什么播客报「宿主未初始化」？**
A：先打开一次「播客 RSS 频道」页，完成频道配置后再运行播客工作流。

**Q：会不会重复发同一篇？**
A：默认会去重（来源键或内容指纹任一命中即跳过）。如果确实要重发，关闭该工作流的「与已发内容去重」或换一条来源。

## 7. 资源与费用提醒

工作流会占用模型额度（改写、TTS、视频生成）与浏览器资源，并可能与手动发布竞争平台限流。建议先用「发布前需人工审核」跑一轮，确认产出质量与费用后再开全自动。
